# N11 服务端测试结果回显规范

适用范围：`qa-agents/src/qa_agents/quality_results.py`（唯一渲染器）、
`quality_pipeline.py`（写入 `n11-quality-decision.case_outcomes`）、
`card_copy.py`（N11 记录卡）、`sync_eight_card_progress.py`（刷新任务详情）。

## 目标

打开 N11 任务详情时，不翻 JSON 也能看到：这次测了什么、哪些过了、哪些没过、
每条 case 的完整测试场景、不通过的中文原因，以及对应请求的 TraceId。

## 强制规则

### 1. 只展示实际执行结论

- 来源：N08 shards + lifecycle.json + N25 用例标题。
- 禁止把计划中的用例写成通过。
- 失败原因用人话，禁止把整段 pytest traceback 贴进产出。

### 2. 分组固定

```text
## 服务端测试结果

结论：……

### 通过
- `PC-BE-006-BACKEND` 没权限时保持原权限失败
  - 测试场景：操作者没有查看明细权限时，即使统计图也命中了专用限制，仍应走原来的权限失败，不能改成四个专用限制错误码。
  - 请求 TraceId：
    - `perm_zh`：`FSW-91863.1002-...`

### 不通过
- `PC-BE-003-BACKEND` 多关联关系拒绝查看明细
  - 测试场景：基于多关联关系创建的统计指标，在对象关系校验失败时拒绝查看明细：返回专用错误码 s307011536，中英文提示精确为批准模板。已经能成功解析关联关系、本来就能看明细的路径必须继续成功，不能被提前禁用。普通对象关系异常在未命中多关联原因时，不得被改写成 s307011536。
  - 原因：实际仍返回旧的通用提示「当前场景暂不支持查看明细」，没有返回专用提示「基于多关联关系创建的统计指标，暂不支持查看明细」
  - 请求 TraceId：
    - `mr_fail_zh`：`FSW-91863.1002-...`

### 未执行
- `PC-E2E-001` Web 统计图与拼表明细提示一致
  - 测试场景：同一不支持查看明细场景下，Web 统计图和 Web 拼表走同一套后端原因：错误码、当前语言提示、指标参数、后端原因都要一致。
  - 原因：E2E 尚未接入，已按策略跳过
```

### 3. 名称必须带完整中文测试场景

- 第一行：`` `用例ID` `` + 短标题，短标题来自批准中文用例卡标题或 `CASE_SCENE_ZH`。
- 下一行必须写 `测试场景：` + **完整测试场景原文**（批准用例卡的「测试场景」段落），不能只写「多关联关系拒绝查看明细」这种四五个字的缩写。
- 优先顺序：编译用例上的中文 `scenario` / `test_scenario` → `CASE_SCENARIO_ZH` → 中文预期描述合成。
- 禁止把英文 IR title、错误码、`resource_key` 当测试场景。

### 3.1 不通过原因必须是中文产品语义

- 必须说明「实际发生了什么、本应发生什么」，用人能看懂的提示文案，而不是只写 `期望 s307011536，实际 s307050002`。
- 错误码要翻译成批准中文提示，例如 `s307011536` → 「基于多关联关系创建的统计指标，暂不支持查看明细」，`s307050002` → 「当前场景暂不支持查看明细」。
- 缺字段也要说人话：缺 `Error.Params` → 无法拼出带指标名的结果集筛选提示；缺 `Error.Code` → 无法确认是否返回了专用错误。
- 禁止把整段 pytest traceback 贴进产出。

### 4. TraceId 必须是实际请求

- Trace 契约见 `fxiaoke-platform-trace-id`：回显查询参数 `traceId`（`FSW-企业账号.员工ID-xxxx`）。
- 禁止把自造的 `QA-uuid` 或 `x-trace-id` 当任务详情主 Trace。
- 没有记录时写 `未记录`，禁止编造。
- 优先展示 `test` 阶段请求；没有 test TraceId 时再展示 setup。

### 5. 挂载位置

N11 记录卡：`## 产出` 之后、`## 你需要处理` 之前。
