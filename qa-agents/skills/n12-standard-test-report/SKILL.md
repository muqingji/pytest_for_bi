# N12 标准测试报告回显规范

适用范围：`quality_report.py`（唯一报告卡片渲染器）、`quality_pipeline.py`（报告数据来源）、
`card_copy.py`（挂载位置）、`sync_eight_card_progress.py`（读取和刷新 N12 任务详情）。

## 目标

打开 N12“质量报告发布”任务详情，在“产出”中直接读到可用于测试结论沟通的完整中文报告，
不需要下载 JSON、Markdown 或 HTML，也不需要跳到其他子任务拼结论。

## 强制格式

报告标题固定为“标准测试报告”，正文按以下顺序展示：

1. 报告结论：测试结论、发布建议和一句话结论摘要。
2. 测试概况：运行 ID、纳入报告数、实际执行数、通过/不通过/未执行数、待跟进缺陷数。
3. 准出依据：说明哪些实际证据支持或阻断发布，禁止只显示内部状态码。
4. 用例执行明细：按通过/不通过/未执行分组；每条包含中文短标题、完整测试场景、实际测试数据、中文失败或跳过原因，以及实际请求的 `FSW-...` TraceId。
5. 风险与后续动作：明确缺陷修复复测、未执行项补测和报告反馈入口。

## 数据与语义约束

- 只从 N12 Artifact 和其绑定的 N11 `case_outcomes` 确定性生成，禁止模型补写或猜测结果。
- 计划用例不能算作通过；统计口径必须与逐用例明细一致。
- 面向用户使用中文产品语义；`completed_with_defects`、`pending` 等内部状态必须翻译。
- 失败原因和 TraceId 沿用 `n11-quality-result-display` 与 `fxiaoke-platform-trace-id` 规范，禁止粘贴 traceback 或伪造 TraceId。
- 每个 case 必须列出本轮实际使用的测试数据。数据来自 `constructed-test-assets.json` 中同 `case_id` 的已构造资产，格式固定为“资产类型：`中文名称`（`真实资源 ID`）”；统计图必须展示实际图表名称和 `BI_...` ID，关联的指标、自定义维度、报表、交叉表、驾驶舱或拼表也要逐项展示。
- 已执行 case 没有资产绑定时写“未记录（需补充实际资产证据）”；未执行 case 写“本轮未执行，未使用实际测试数据”。禁止从 case 标题、资源 key 或请求参数猜测名称和 ID。
- N12 报告正文必须直接位于任务详情的 `## 产出` 中；附件只作为审计副本，不能替代正文。
- 已存在的 N12 任务也必须在报告数据可用时刷新 description，不能只同步状态。

## 验收

- N12 详情无需打开附件即可回答：测了什么、结果如何、是否建议发布、为何、下一步做什么。
- 汇总数字与逐用例分组一致。
- 每个 case 均能看到实际测试数据；使用统计图时能直接看到图表中文名称和真实 ID。
- 不通过项包含中文原因和实际 TraceId；未执行项明确说明原因且不计为通过。
- 渲染器单测、卡片挂载测试和同步刷新测试通过。
