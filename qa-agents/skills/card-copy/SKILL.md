# Multica 卡片文案规范

适用范围：`workflow_center.py`（阶段卡）、`card_copy.py`（统一文案源，
覆盖 A02/A03/A05/A06/A08/A09/A11/A14/A15/A22 节点卡）、
`human_correction.py`（人工修正卡）、`g01_review.py`/`g02_review.py`（审核卡）、
`scripts/sync_eight_card_progress.py`（节点/Agent 任务卡创建）。

## 目标

任何一张卡打开后，不看上下文也能回答三个问题：这张卡是干什么的、为什么要做、
现在需要我做什么。

## 强制规则

### 1. 标题一眼可读

- 阶段卡：`[run_id] C3 测试设计与审核`（保持现状，节点名用中文全称）。
- 节点/Agent 任务卡：`[run_id] A08 测试设计`；修正轮加“修正”字样（如 `A08 测试设计修正`）。
- 人工修正卡：`【人工修正】测试设计（A08）· N 个问题待授权`，禁止 `Human A08 correction ... [hash]` 这类内部命名。
- 审核卡：`[run_id] G01 范围与口径审核 · N 项待确认`、`[run_id] G02 用例设计确认 · N 项待拍板`（保留 `[run_id]` 前缀，供同步器按标题发现节点卡）。
- 禁止把 request hash、review key、issue_code 等内部标识当标题主要信息。

### 2. 正文统一五段式

每张卡片正文必须按顺序包含：

```text
## 目标      这张 Issue 要完成什么
## 背景      为什么要做这件事
## 范围      改哪些、不改哪些（包含/不包含两组）
## 输入材料  设计稿、日志、链接、附件等
## 验收      完成后要看到什么结果、哪些现象不能被破坏
```

阶段卡在五段式之外保留运营段落：`## 阶段任务`、`## 当前进度`、`## 产出`、
`## 异常处理`、`## 人工操作`、`## 完成标准`。
C5/C6 在 `## 产出` 之后按 `constructed-asset-card-display` 追加 `## 已构造测试数据`；
N08 记录卡同样挂在 `## 产出` 之后。渲染必须走 `card_copy.constructed_assets_markdown`。

### 3. 传递参数的卡片必须单独列操作明细

需要人工决策/授权/审核的卡（人工修正卡、G01/G02 审核卡），在“输入材料”之后、
“验收”之前增加操作明细段落，逐条写清楚“我要操作什么”：

- 人工修正卡：`## 本次授权明细`，每条含 通俗标题、问题一句话、修正方案、涉及用例/期望项。
- G02 审核卡：`## 你需要拍板`，只列出用例设计未冻结的产品口径（产品场景 / 设计不确定点 / 请拍板）。禁止把全部父用例当成审批项。
- G02 审批项：必须让产品人员看出「哪个功能场景还没定、要拍什么板」。已写死的用例只放在「已按冻结规则写完」摘要里。
- G02「输入材料」第一行必须引导打开附件 `case-cards.md` 阅读完整中文用例（测试场景 / 前置条件 / 测试步骤 / 预期结果）。JSON 只能作为技术附件。
- G01 审核卡：`## 你需要审核什么` + `## 你需要怎么做`，沿用现有格式。

### 4. 文案禁止出现内部噪音

- 面向用户的段落不得以 `issue_code`、`request_hash`、`review_key`、JSON 路径为主信息。
- 技术细节可保留在“输入材料”附件或文末追溯区，不放在目标/背景/范围里。
- 每条操作都要有明确二选一或枚举动作（如 done 授权 / cancelled 终止 / blocked 回流）。

## 每张卡的类型与文案来源

| 卡片类型 | 生成位置 | 标题 | 正文 |
| --- | --- | --- | --- |
| 父工作流卡 | `workflow_center.py` | `[requirement_id] 标题` | 五段式 + 状态驾驶舱 |
| 阶段卡 C1-C8 | `workflow_center.py` | `[run_id] Cn 中文名` | 五段式 + 运营段落 |
| 节点/Agent 卡 | `sync_eight_card_progress.py` | `[run_id] NODE 中文名(修正)` | 五段式 |
| 人工修正卡 | `human_correction.py` | `【人工修正】… · N 个问题待授权` | 五段式 + 授权明细 |
| G01 审核卡 | `g01_review.py` | `[run_id] G01 范围与口径审核 · N 项待确认` | 五段式 + 审核明细 |
| G02 审核卡 | `g02_review.py` | `[run_id] G02 用例设计确认 · N 项待拍板` | 五段式 + 未冻结口径 |

## 修改约束

- 文案统一收敛在 `qa-agents/src/qa_agents/card_copy.py`：阶段文案表 `STAGE_CARD_COPY`、
  节点文案表 `NODE_CARD_COPY`、各卡标题/正文构建函数。
- 渲染器只调用 `card_copy` 构建器，禁止在各模块内裸拼卡片标题或五段式正文。
- 修改后必须同步更新 `human-readable-workflow-output` 的验收清单并跑全量测试。

## 验收清单

- [ ] 所有卡片标题一眼可读，无内部 hash/code 标题
- [ ] 每张卡都有 目标/背景/范围/输入材料/验收
- [ ] 需人工决策的卡都有独立操作明细段落
- [ ] 新增卡片文案必须走 `card_copy.py` 构建器
- [ ] C5/C6/N08 构造成功后按分类回显已构造测试数据，不把 JSON 路径当主信息
- [ ] 全量测试通过（`cd qa-agents && ../.venv/bin/python -m pytest -q`）
