节点运转流程

每个节点都遵循同一条调度与验收链路。区别只在中间执行体：Agent 节点由模型输出候选 Artifact， 确定性节点由本地程序计算，人工 Gate 由白名单成员提交结构化评论。阶段卡只做展示，不能反向驱动调度。

1. 事件唤醒monitor 扫描评论、Issue、Run、Artifact 与注册表变化
2. 状态对账读取 Spec、上游 Artifact、策略和 DAG，确认当前节点
3. 计划授权Planner 生成节点计划，Supervisor 校验并写入计划哈希
4. 分发执行创建 Agent Issue 或运行确定性程序；单 Run 加锁串行
5. 输出校验校验 Schema、语义、来源、附件、模型、工具轨迹和哈希
6. 推进投影入库 Artifact → 更新 Spec → 刷新 C1-C8 → 派发下一步
Agent 节点下载冻结输入 → 生成结构化候选 → 附件/评论交付 → ingest-multica 校验 → 合法则入库

测试设计修正闭环

A08 → A09 → N04：契约失败自动定向修正；预算耗尽进入人工恢复；G02 退回后走 A08 v1.4.0，再经 A09 / N04 复审。每一轮反馈 ID 精确绑定，旧问题不能冒充新修正。

Agent 输出摄入闭环

Issue / Run / 附件 / 评论 → 任务与工具轨迹审计 → Schema 与语义校验 → 上游哈希校验 → Artifact 入库 → 投影 C1-C8。非法输出拒收，不能靠改卡片状态放行。

人工反馈评估闭环

人工修正保存原始输出、修正结果和错误类型，进入独立 Oracle 评估集；用于 Prompt、 Profile、策略和知识版本回归，指标恶化时停止灰度并回滚。
Agent：模型判断 / 候选 确定性节点：程序校验 / 执行 人工 Gate：签核与决策 策略决策：分流 / 回流 / 收口 风险边界：blocked / inconclusive
分享时的边界说明：当前是可审计参考实现，已真实打通 Multica 测试设计链和部分执行链； 生产隔离 Runner、TAPD/MR/发布/通知 Adapter、A16 E2E、生产模型灰度和完整语义评估仍未完成。 `completed_with_gaps`、本地提交或人工批准都不能解释为生产发布放行。
