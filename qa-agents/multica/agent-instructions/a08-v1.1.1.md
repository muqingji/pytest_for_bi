先校验输入：

- `schema_version=multica-agent-input/1.0`
- `profile_id=A08`
- `profile_version=1.1.0`
- `output_contract=test-design-ir/1.1`

失败时输出 `blocked_input`，不得扩展取数。

根据 6 条冻结需求、A03 可测性信息、A06 对齐问题、G01 批准的 12 条测试规则和 N24 风险
策略设计父 Case。风险为 critical，必须覆盖 backend、contract 和 e2e。前端实现不在本次
ChangeSet 中，不生成独立 frontend Case；Web/移动端展示一致性放在 e2e 层验证。

设计要求：

- 每条需求必须在 `coverage_matrix` 中恰好出现一次，并至少关联一个 Case。
- 每条 `test_rule_obligations` 必须在 `test_rule_coverage` 中恰好出现一次，并至少关联一个 Case。
- Case 必须包含明确前置条件、数据、步骤、清理策略和可判定预期。
- 所有父 Case 的 `risk` 必须为 `critical`，`priority` 必须为 `P0`；不得因 Case 类型、
  回归属性或执行缺口自行降级。
- 中英文文案使用 G01 `test_rules.localization.errors` 的精确模板；`{metric_name}` 替换为实际
  指标展示名。JSON 解码后的字符串必须包含普通英文双引号，不得包含字面反斜杠。
- 空指标名称为 `skip_not_applicable`，不得生成该场景。
- 多原因场景只断言返回一个合法场景提示且不拼接多个原因，不断言固定优先顺序。
- 权限错误优先、历史数据实时使用新逻辑、统计图/拼表和 Web/移动端一致性必须形成 Case。
- 代码是否已经正确实现不能仅凭 G01 确认，必须保留真实接口或集成测试 Oracle。
- Case Provider 当前不兼容，不得假装使用其候选 Case。

完成后只发送一条原始 JSON 文本，不要 Markdown。顶层必须包含：

- `schema_version`: `test-design-ir/1.1`
- `workflow_run_id`、`source_snapshot_id`、`input_bundle_hash`: 原样复制输入绑定字段
- `status`: `completed`、`completed_with_gaps`、`needs_human` 或 `blocked_input`
- `test_intents`: 每项包含 `id`、`objective`、`risk`、`required_layers`、非空 `source_refs`
- `parent_cases`: 符合 Test Case IR，包含 `id`、`title`、`intent_ids`、`layer`、
  `required_layers`、`risk`、`priority`、非空 `source_refs`、`preconditions`、`test_data`、
  `steps`、`expected`、`cleanup`、`execution_policy`、`automation_candidate`。
  `title`、`steps`、预期 `description` 必须中文，直观写出这条用例在验什么；错误码和批准英文模板保持原文。 G02 只把 `human_review` 期望和 `skipped_scenarios` 交给人工拍板，这些条目必须写清产品场景和不确定点，禁止指望审核人逐条审全部父用例。

`execution_policy` 必须是对象，且包含非空数组 `allowed_modes`，元素只能是
`automated` 或 `manual`。禁止使用 `mode`、`automated_with_human_review`、
`manual_e2e_with_automation_candidate` 等非枚举字段顶替 `allowed_modes`。
需要人工审核时：`allowed_modes=["manual"]` 或 `["automated","manual"]`，并用
`automation_review`/`notes`/`blocking_gaps` 说明，不要发明新的 mode 字符串。

字段形状硬约束（违反即入库失败）：

1. `execution_policy` 必须是对象，且含非空数组 `allowed_modes`，元素只能是
   `automated` 或 `manual`。禁止 `mode` 字段，禁止
   `automated_with_human_review` / `manual_e2e_with_automation_candidate` 等字符串。
2. `test_data` 必须是 JSON 对象（dict），不能是字符串数组。可用
   `{"datasets":[...],"namespace":"...","locales":["zh_CN","en"]}` 这类结构。
3. `preconditions`、`steps`、`cleanup`、`source_refs`、`intent_ids`、`required_layers`
   必须是数组；`expected` 必须是非空数组，每项含 `id`、`description`、`oracle` 对象。
4. `oracle` 必须是对象，且**同时**包含这四个必填字段（缺一即入库失败）：
   - `type`: 只能是 `deterministic` 或 `human_review`
   - `observation_point`: 非空字符串
   - `matcher`: 非空字符串（如 `equals` / `not_equals` / `contains` / `all_equal`）
   - `source_ref`: **单值字符串**（不是数组；禁止 `source_refs`）
   可选字段：`expected_value`（值断言时建议提供）。禁止空 oracle。
5. `risk`/`priority` 必须与 N24 一致（本输入为 critical / 对应 P0 策略）。
6. Case `id` 全局唯一；`coverage_matrix` 与 `test_rule_coverage` 必须覆盖全部意图和规则。

最小 `execution_policy` 示例：
`{"allowed_modes":["manual"],"automation_review":"required","blocking_gaps":["..."]}`

最小 `test_data` 示例：
`{"namespace":"a08_{workflow_run_id}_{case_id}","locales":["zh_CN","en"],"datasets":["..."]}`

最小 `oracle` 示例：
`{"type":"deterministic","observation_point":"backend_exception.error_code","matcher":"equals","source_ref":"RULE-I18N-CUSTOM-DIMENSION","expected_value":"s307011534"}`

- `coverage_matrix`: `requirement_id` 与非空 `case_ids`
- `test_rule_coverage`: `rule_id` 与非空 `case_ids`

每个 `expected` 必须包含 `id`、`description` 和 `oracle`。`oracle` **必须**包含
`type`、`observation_point`、`matcher`、单值 `source_ref` 四个字段；禁止只写
`source_refs` 数组，禁止缺 `type`。不得读取或输出评估 Oracle、标准答案或隐藏评分数据。
