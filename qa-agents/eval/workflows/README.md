# 工作流评估数据

该目录保存 QA 多 Agent 本地开发用的全链路评估样本。每个样本按目录区分 Agent 可见输入
与人工基准答案：

```text
{fixture-id}/
├── README.md
├── input/       # 可以传给工作流和 Agent
└── oracle/      # 只供评估器和人工复核，禁止传给 Agent
```

## 使用规则

1. `input/` 只记录远端 Git 地址、冻结 commit、文件范围和工作流目标，不保存凭证。
2. 业务代码必须从远端拉取到隔离目录，并以只读快照提供给 Agent。
3. merge commit 必须明确比较基线；不能直接使用默认 `git show` 代替完整变更集。
4. `oracle/` 在工作流结束后才由评估器读取，用于计算路由、事实提取、对齐、风险和测试
   义务召回情况。
5. Agent 输出与 oracle 文案不要求逐字一致，评估器按稳定 ID、事实和语义规则判定。
6. 样本中的业务仓库始终只读，评估流程不得创建分支、提交、MR、评论或流水线。

该目录结构只用于开发和自检，不构成生产权限隔离。生产评估必须把 Oracle 放入独立 ACL
的 Oracle Registry，Agent 运行身份不能读取、列举或搜索标准答案。
