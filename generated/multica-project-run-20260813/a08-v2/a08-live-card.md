## 目标

完成“统计图查看明细限制原因提示优化”的测试设计，形成可执行、可追溯的 backend、contract、e2e 测试 Case。

## 背景

需求涉及四类专用限制原因、统计图与拼表入口一致性、多语言、历史资产兼容，以及 Web/H5 运行时接口等价性。风险等级为 critical，必须覆盖 backend、contract、e2e 三层。

## 范围

包含：
- 自定义维度、结果集筛选、多关联、动态关联四类限制。
- 普通、聚合、计算、同环比指标和多指标名称。
- 统计图、拼表、Web、H5 及历史资产。
- 权限错误、非目标错误和成功路径回归。

不包含：
- 不修改业务代码。
- 不把故障注入边界 Case 当作本轮可执行自动化。
- 不在接口与参数完全相同时重复验证 H5 UI。

## 产出

当前设计共 7 个测试意图、11 个父 Case：Backend 6 条、Contract 2 条、E2E 3 条；覆盖 7/7 条需求、12/12 条冻结测试规则。

### Case 清单

- `PC-BE-001` 自定义维度在维度和数据范围中的限制判定
- `PC-BE-002` 结果集筛选指标名称解析、多指标和多语言判定
- `PC-BE-003` 多关联原因识别及成功关系解析回归
- `PC-BE-004` 特殊 what 与 what-list 动态关联范围和替换边界
- `PC-BE-005` 多原因单提示和权限错误优先保护
- `PC-BE-006` 成功响应、非目标错误和历史配置实时兼容性
- `PC-CT-001` 四类专用错误的中英文契约和参数渲染
- `PC-CT-002` 失败响应结构、指标参数和非目标契约兼容
- `PC-E2E-001` 统计图与拼表四类限制原因端到端一致性
- `PC-E2E-002` Web 与移动端运行时路由和提示一致性
- `PC-E2E-003` 历史统计图和拼表不迁移实时应用新逻辑

### 关键设计结论

- 多限制同时命中：只展示一个实际命中的专用提示，不固定业务优先级。
- 多个结果集指标：展示全部指标名称。
- 同环比：在统计图指标配置层构造，不在指标内部构造。
- 多关联与动态关联：分别校验 `s307011536`、`s307011537`，并保留成功关系解析路径。
- 拼表：与统计图使用相同后端原因、错误码、文案和参数。
- H5：先比较运行时路由、API 和参数；完全相同时跳过重复 H5 UI 自动化。
- 历史资产：不迁移、不重新保存，实时应用新判断逻辑。
