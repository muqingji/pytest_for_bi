## 测试 Case

### PC-BE-001 自定义维度位置判定与专用原因

- 类型：backend
- 测试场景：统计图维度包含自定义维度，数据范围仅含普通字段；统计图数据范围包含自定义维度，维度仅含普通字段；维度和数据范围均不含自定义维度的对照图表
- 执行步骤：分别构造自定义维度位于维度和数据范围的请求，并调用真实查看明细服务。；采集每次调用的限制原因、错误 key、错误码和响应。；调用不含自定义维度的对照请求，确认不会因本规则被拒绝。
- 预期结果：维度位置命中自定义维度限制。；数据范围位置命中同一自定义维度限制。；无自定义维度的对照请求不返回自定义维度专用错误。

### PC-BE-002 结果集筛选指标名称解析与多指标传递

- 类型：backend
- 测试场景：普通指标按结果集筛选且 Filter.fieldName 为营收或 Gross Revenue；聚合指标按结果集筛选且 fieldName 缺失、fieldId 元数据名称有效；计算指标按结果集筛选且前两级名称缺失、当前语言动态展示名有效；同环比指标按结果集筛选且名称可解析；两个按结果集筛选指标，名称分别为营收和订单数
- 执行步骤：依次使用普通、聚合、计算和同环比指标调用真实查看明细服务。；分别验证名称从 Filter.fieldName、fieldId 元数据和当前语言动态展示名解析。；使用两个受限指标调用服务并采集传给业务异常的指标名称参数集合。
- 预期结果：四类指标均返回结果集筛选专用错误。；单指标名称严格按 fieldName、fieldId 元数据、当前语言动态展示名顺序解析。；多个受限指标的所有展示名均进入实际业务异常参数，不遗漏且不泄露无权限名称。

### PC-BE-003 多关联与动态关联真实范围及关系解析回归

- 类型：backend
- 测试场景：业务对象数或拓扑满足实际多关联判定且关系解析返回既有已知不支持错误；工单主题下业务流程任意字段的动态关联指标；工单主题下业务流程任务任意字段的动态关联指标；工单主题下服务记录任意字段的动态关联指标；普通 what 或 whatlist 关系负样本；候选多关联或动态关联但关系解析成功的样本
- 执行步骤：查询测试环境的实际对象、字段 ID、whatFieldType 和关系元数据并绑定测试数据。；对多关联和三个动态关联正样本注入既有已知关系不支持结果后调用查看明细。；对普通关系负样本调用相同入口。；令候选受限关系解析成功并调用查看明细，比较改造前后的成功结果。
- 预期结果：多关联正样本仅在既有关系解析失败时返回多关联专用错误。；三个批准的动态关联对象范围均返回动态关联专用错误。；普通关系负样本不返回动态关联专用错误。；关系解析成功时保持成功，不被候选原因预判禁用。

### PC-BE-004 多原因单提示、权限优先与非目标异常透传

- 类型：backend
- 测试场景：同时命中自定义维度和结果集筛选；同时命中动态关联和多关联；受限图表但当前用户无查看明细权限；关系查询参数错误；关系查询超时；关系元数据服务异常
- 执行步骤：分别提交两组多原因请求并采集最终响应。；以无权限用户提交受限请求并与既有权限错误基线比较。；依次注入参数、超时和元数据服务异常并调用关系入口。；检查返回消息数量、错误码及消息内容。
- 预期结果：多原因请求仅返回一个实际命中的合法专用提示，不拼接多个原因且不固定断言优先顺序。；无权限用户保持既有权限错误，指标名称不可绕过权限泄露。；参数、超时和元数据服务异常原样透传，不映射为关联专用错误。

### PC-CT-001 四类错误码、中英文模板与参数契约

- 类型：contract
- 测试场景：自定义维度限制；结果集筛选且 zh_CN 指标展示名为营收；结果集筛选且 en 指标展示名为 Gross Revenue；多关联限制；动态关联限制
- 执行步骤：分别以 zh_CN 和 en 调用四类受限场景的真实接口。；解码 JSON 并采集 errorCode、errorKey、message 和 metricName 参数。；逐字符比较中英文消息，确认英文双引号为普通字符且不存在字面反斜杠。；验证结果集场景通过实际业务契约传输全部指标展示名。
- 预期结果：自定义维度中文响应精确为批准模板。；自定义维度英文响应精确为批准模板。；结果集筛选中文响应使用实际指标展示名。；结果集筛选英文响应使用普通双引号包围实际指标展示名。；多关联中英文消息及错误码与批准契约一致。；动态关联中英文消息及错误码与批准契约一致。

### PC-CT-002 历史数据实时新逻辑与接口兼容性

- 类型：contract
- 测试场景：历史自定义维度统计图；历史结果集筛选统计图和拼表；历史多关联与动态关联指标；历史成功查看明细图表；小时分钟过滤、复杂虚拟指标、权限及普通关系异常负样本
- 执行步骤：不迁移历史配置，直接用当前服务查询历史统计图和拼表。；记录目标场景当前错误码和消息。；比较成功请求的查询参数、SQL、分页和成功响应基线。；比较非目标失败的错误码、异常类型和响应结构基线。
- 预期结果：历史目标场景实时使用新专用逻辑，无需迁移。；历史成功查询的参数、SQL、分页和响应保持不变。；非目标错误码及异常身份保持不变。；失败响应结构除批准的错误码、消息和参数外无变化。

### PC-E2E-001 Web 统计图与拼表限制提示一致性

- 类型：e2e
- 测试场景：自定义维度限制的统计图与拼表配对资产；结果集筛选限制的统计图与拼表配对资产；多关联限制的统计图与拼表配对资产；动态关联限制的统计图与拼表配对资产
- 执行步骤：分别从 Web 统计图和拼表入口对四类配对资产执行查看明细。；采集每个入口的后端原因、错误码、locale 消息和指标参数。；逐场景比较两个入口的接口响应和最终可见提示。；确认拼表结果集筛选沿用统计图的批准文案。
- 预期结果：统计图和拼表的后端原因、错误码、locale 消息及指标参数逐场景全部一致。；两个入口均只展示一个与实际命中原因对应的提示。；拼表结果集筛选展示与统计图完全相同的批准文案。

### PC-E2E-002 Web 与移动端运行时路由和展示一致性

- 类型：e2e
- 测试场景：自定义维度限制资产；结果集筛选限制资产；多关联限制资产；动态关联限制资产；Web 与移动端相同权限和相同 locale 会话
- 执行步骤：查询并记录 Web 与移动端查看明细的实际运行时路由。；分别在两端触发四类受限场景并采集 API、参数、错误码、消息和指标参数。；先比较两端路由、API 与参数；完全相同时合并重复移动 UI 变体，否则逐路由执行。；在 zh_CN 和 en 下比较两端最终可见提示。
- 预期结果：Web 与移动端对相同资产产生相同限制原因、错误码和指标参数。；两端在相同 locale 下展示完全相同的批准消息。；仅当移动端与 Web 使用相同运行时路由、API 和参数时才跳过重复移动 UI 变体。
