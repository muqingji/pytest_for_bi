# 智能提醒助手技术方案

> 状态：技术方案草稿，等待 MVP 范围确认后进入编码。

## 1. 技术目标

用一个可离线运行的最小项目验证以下业务闭环：

~~~text
用户与任务数据
→ 特征读取
→ 提醒决策
→ 模拟发送
→ 行为事件
→ 任务完成归因
~~~

首版优先保证决策逻辑可解释、可测试、可重复演示，不引入真实 Push、消息队列和机器学习基础设施。

## 3. 核心领域对象

- User：用户标识、分层、时区、Push 权限。
- DailyTask：任务日期、任务数量、完成数量、截止时间。
- ReminderPreference：提醒开关、免打扰时段、可用渠道。
- ReminderDecision：是否提醒、排程时间、原因、策略版本、幂等键。
- ReminderDelivery：发送状态、重试次数、失败原因。
- BehaviorEvent：发送、到达、打开、开始、完成等事件。

## 4. 决策引擎

输入：

- 用户和任务状态。
- 最近行为特征。
- 提醒设置和权限。
- 当前时间、时区和已有发送记录。

输出：

~~~text
Decision {
  should_remind
  scheduled_at
  channel
  reason_code
  strategy_version
  dedupe_key
}
~~~

规则优先级：

1. 用户关闭提醒。
2. 任务已完成。
3. 任务已过期。
4. 达到每日频控。
5. 免打扰时段。
6. Push 权限关闭时降级。
7. 连续不活跃低频处理。
8. 选择候选活跃窗口。

决策引擎尽量实现为无副作用函数，发送和事件记录由外层服务负责。

## 5. 幂等、重试和状态

建议幂等键：

~~~text
user_id + task_date + strategy_version + channel
~~~

调度任务重跑时先查询幂等键。发送失败最多重试一次，重试不得生成新的幂等键，也不能绕过每日频控。

发送前再次读取任务状态，防止用户已经完成任务后仍发送旧提醒。

## 6. 时间处理

- 所有领域时间使用带时区的时间类型。
- 用户时间优先使用设备时区，Demo 默认 Asia/Shanghai。
- 免打扰跨午夜时按两个时间区间处理。
- 候选提醒时间必须早于任务截止时间。
- Demo 提供可注入时钟，支持快速推进时间。

## 7. Demo 简化项

| 生产能力 | Demo 方案 |
| --- | --- |
| 用户和任务数据库 | 内存或本地 JSON |
| 调度系统 | 可注入时钟和手动推进 |
| Push 厂商 | Mock channel |
| 站内消息中心 | 本地事件记录 |
| 用户行为埋点 | 内存事件表或本地文件 |
| 策略配置中心 | 代码内版本化规则 |

## 8. 待确认技术决策

- 主实现采用 Go 还是 TypeScript。
- 是否需要 HTTP API，还是使用 CLI/本地 Demo。
- 是否保留站内提醒作为 MVP。
- 是否需要前端展示，还是先完成 API 和可读日志。
- 真实项目中持久化、调度和 Push 适配器的替换方式。

## 9. 系统实现流程

产品方案中的用户流程由以下技术模块支撑：

~~~text
任务与用户数据
→ 特征读取
→ 决策引擎
→ 调度和频控
→ 渠道适配器
→ 发送状态
→ 行为事件
→ 任务完成归因
~~~

系统服务负责执行和记录，不负责定义用户侧任务页面的交互内容。

## 10. 决策和事件技术契约

决策对象建议包含：

~~~text
should_remind
scheduled_at
channel
reason_code
strategy_version
dedupe_key
~~~

建议幂等键为：

~~~text
user_id + task_date + strategy_version + channel
~~~

发送前重新读取任务状态，防止任务已完成后发送旧提醒。发送失败最多重试一次，重试使用相同幂等键。

每个行为事件携带 decision_id 和 strategy_version，便于测试和后续线上归因。

## 11. 测试辅助实现边界

技术方案只定义测试适配器与核心实现的接口边界；具体用户、任务和行为数据不放在本文件。

- 可注入时钟和手动推进时间。
- Mock Push 与站内提醒适配器。
- 本地事件时间线。
- 重复执行调度的幂等检查。
