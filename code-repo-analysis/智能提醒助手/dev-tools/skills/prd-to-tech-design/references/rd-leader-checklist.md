# RD leader 审查清单

用于第 5 步。每条都要给出文件位置证据，不能只给结论。标注“阻塞”的项未解决时，方案不能进入技术评审。

## 1. 需求边界

| 检查点 | 阻塞判定 |
| --- | --- |
| 每条 P0 需求是否有模块、入口、数据落点、异常处理 | 缺任一项即阻塞 |
| FR 编号与 PRD 是否一致，有无自行新增或改名 | 有即阻塞 |
| P1、P2 是否被写进了实现范围 | 被写入即阻塞 |
| 技术目标是否可验证（对照 AC 或指标） | 只有口号式目标即阻塞 |

## 2. 异常与边界

| 检查点 | 阻塞判定 |
| --- | --- |
| 超时、失败、未知状态三类是否分别有处理策略 | 缺任一即阻塞 |
| 依赖不可用时是失败关闭还是降级，是否明确 | 未明确即阻塞 |
| 异常链路占第 4 章正文比例是否达到 40% | 明显低于 40% 即建议整改，缺整类异常即阻塞 |
| 边界场景（临界时间、跨天、并发、重复执行）是否覆盖 | 缺并发与重复执行即阻塞 |

## 3. 幂等与并发

| 检查点 | 阻塞判定 |
| --- | --- |
| 有价资源流动是否给出幂等设计 | 涉及但未给即阻塞 |
| 幂等键的取值、唯一约束位置是否明确 | 未明确即阻塞 |
| 并发抢占是否有条件更新或租约机制 | 无即阻塞 |
| 重试次数、重试幂等性、重试是否突破配额 | 未说明即阻塞 |

## 4. 数据与存储

| 检查点 | 阻塞判定 |
| --- | --- |
| 表结构是否有字段、类型、索引、唯一键 | 缺唯一键或索引即阻塞 |
| 容量估算是否与业务量级匹配，保留与归档策略是否给出 | 缺失即建议整改 |
| 缓存是否被当作频控或状态的事实来源 | 是即阻塞 |
| 数据一致性由谁保证（事务、唯一约束、补偿） | 未说明即阻塞 |

## 5. 接口

| 检查点 | 阻塞判定 |
| --- | --- |
| 命名规范、限流评估、鉴权方式是否写明 | 缺失即阻塞 |
| 参数与返回值语义、错误码分类是否完整 | 缺未知状态处理即阻塞 |
| 是否允许客户端直接传决策结果等敏感字段 | 允许即阻塞 |
| 敏感信息是否最小化（无姓名、手机号、正文、成绩） | 有即阻塞 |

## 6. 定时任务与调度

| 检查点 | 阻塞判定 |
| --- | --- |
| 分片、并发、幂等、重跑是否说明 | 缺幂等或重跑即阻塞 |
| 积压、失败、重复执行是否有监控与告警 | 无即阻塞 |
| 是否依赖无限重试或长事务 | 是即阻塞 |

## 7. 变更保障

| 检查点 | 阻塞判定 |
| --- | --- |
| 灰度开关、放量步骤、回滚方案是否可执行 | 缺回滚即阻塞 |
| 止损手段与数据修复边界是否明确 | 无止损即阻塞 |
| 监控指标是否覆盖评估、排程、发送、渠道与数据一致性 | 缺发送与一致性即阻塞 |
| 补偿逻辑是否可能造成重复发放 | 是即阻塞 |

## 8. 成本、排期与冗余

| 检查点 | 阻塞判定 |
| --- | --- |
| 第 7 章成本评估是否给量级与影响因素 | 空白即阻塞 |
| 排期是否给前置条件与责任人 | 只有“待定”即建议整改 |
| 是否复述 PRD 的业务背景、规则表或指标定义 | 大段复述即建议整改 |
| 是否存在同一结论多处重复、重复表格 | 存在即建议整改 |
| 是否堆砌与 MVP 无关的技术名词或生产拓扑 | 存在即阻塞 |
| 是否把 Demo 简化项写成生产能力 | 未声明简化即阻塞 |
