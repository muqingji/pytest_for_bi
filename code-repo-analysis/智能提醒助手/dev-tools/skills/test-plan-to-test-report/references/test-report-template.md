# 测试报告模板

报告默认写入 `docs/test-report.md`，沿用项目现有结构。缺少“测试环境 / 测试命令 / 自动化测试结果 / 已知限制”任一项，报告都不可复核。

## 必要章节

````markdown
# 测试报告

> 状态：<本轮覆盖的 FR 与范围>；<已联调 / 未联调的真实依赖>

## 1. 测试环境

- 操作系统与架构
- 运行时版本与工具链来源
- 依赖安装命令与结果

## 2. 测试命令

~~~bash
<可直接复制的命令>
~~~

## 3. 自动化测试结果

| 项目 | 结果 |
| --- | --- |
| 执行命令 | |
| 通过 / 失败 / 跳过 / 未执行 | |
| 覆盖的功能与分支 | |

## 4. AC 覆盖与追踪

| AC | 用例 ID | 分层 | 状态 | 证据位置 |
| --- | --- | --- | --- | --- |

## 5. 功能演示场景

- [x] <已演示场景>：<观察到的结果>
- [ ] <未演示场景>：<原因，且写明属于哪个后续 FR>

## 6. 已知限制

<未覆盖范围、Mock 与真实渠道的区别、不能由此得出的结论>
````

## 写作要求

- 命令与结果成对出现；每条结论能追溯到命令输出或用例 ID。
- 结果表区分通过、失败、跳过、未执行；失败用例如实保留，不得合并或省略。
- 未勾选的演示项必须写原因，不允许留空。
- 使用 Mock、Fixture、本地数据库时明确标注；不得据此得出渠道到达率、打开率或线上指标结论。
- 没有实测的性能、并发、容量结论不得写入。
- 未执行的检查明确写“未执行”，不得写成通过。
