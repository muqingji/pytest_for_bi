# 测试数据构造门禁清单

## 门禁 A：写数据前

- TC 已通过人工审批，前置条件、步骤和预期没有未裁定冲突。
- 自动化映射已确定 TC、case id 和主体文件。
- 每个前置条件已拆成用户、任务、行为、偏好、用量、时间和依赖状态。
- 每个值都有来源；假设、默认值和不可构造项已显式列出。
- 没有要求把 IDL 不支持的服务端状态塞进请求体。
- 用户已确认数据需求矩阵。

## 门禁 B：交付前

- 每个目标 case 都有非空 `test_data`，且至少一个请求字段使用 `{data.xxx}`。
- `test_data.fixture`、`scenario.fixture` 和 Fixture `user_id` 一致。
- Fixture `covers` 包含且默认只包含当前 case id。
- 可变状态不会被不同 case 共享；多步骤状态只在当前 case 内传递。
- 请求体字段均存在于 IDL，没有为构造方便增加业务字段。
- 时间、时区、截止时间和随机值可重复；无法固定的用例仍明确 pending。
- 没有修改 `expected`、业务代码、IDL 或已审批 TC。
- 数据绑定检查、pytest harness、自检收集和自动化映射检查均无阻塞项。
- 报告记录了真实执行命令、退出码和剩余不可构造项。
