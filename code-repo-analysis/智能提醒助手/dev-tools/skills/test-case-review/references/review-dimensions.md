# 评审维度与常见失分形态

阶段 3 按本表逐维评审，每维都要记录证据。没有问题的维度写“该维度无阻塞项”，不要静默跳过。

## 1. 溯源正确性

- 核验方式：实读原文，确认该行内容确实支持这条判定。
- 成熟证据：引用指向规则所在行本身。
- 常见失分：引用指向章节标题行而非规则行；引用指向表格里的别的行；改稿后行号漂移；多条场景引用同一行却推出不同判定；引用的是“建议”段而非“要求”段。

## 2. 覆盖完整性

- 核验方式：把 AC 编号与 PRD 的判定顺序、原因码、频控与免打扰规则逐一对照产物。
- 成熟证据：AC 覆盖矩阵闭合；判定顺序每一步都有场景；出现的每个原因码都能被某条用例触发。
- 常见失分：只覆盖主路径，拒绝分支没有场景；判定顺序中间的某一步被跳过；同一原因码有多个触发条件但只覆盖其中一个；P1 范围被静默省略而不是显式登记。

## 3. 等价类与边界值正确性

- 核验方式：对每条骨架场景检查三类齐不齐，边界取点有没有“等于、前 1、后 1”。
- 成熟证据：有效类、无效类、边界值分别列出；无效等价类逐条独立。
- 常见失分：把多个无效等价类合并成一条用例（会让失败互相遮蔽）；边界只取一端；把“等于阈值”漏掉；阈值类规则没有成对验证（例如流失与回流用同一个 3 天阈值，只验一侧）。

## 4. 判定点可观测性

- 核验方式：问“这条判定在测的那一层能不能看到”。
- 成熟证据：判定点落在响应体、库表或渠道桩的可见输出上；观测不到时已登记为不可测项。
- 常见失分：断言写在接口测不到的层（如事件链路的库表与 outbox、发送时才生成的 Push 文案）；判定点写成“系统应正确处理”这类无观测手段的表述；依赖的桩或调试口尚未存在却没有登记。

## 5. 预期结果确定性

- 核验方式：把预期结果当作断言读一遍，看能否机械判定通过与否。
- 成熟证据：预期值唯一、可比较；含计数、状态、原因码等可直接断言的内容。
- 常见失分：出现“符合预期”“正常返回”“同上”；预期依赖未决口径却未标注；一条用例写多个互斥预期。

## 6. 优先级合理性

- 核验方式：与来源需求比较，并检查风险场景有没有被降级。
- 成熟证据：不高于来源需求；P0 数量与本期范围匹配。
- 常见失分：用例优先级高于其场景；把口径未定的场景标成 P0 却不标注依赖；高频打扰、投诉、越权、数据泄露类风险场景被标成 P1/P2；P0 膨胀到让评审失去筛选作用。

## 7. 前置条件可构造性与契约一致性

- 核验方式：与数据构造说明或 Fixture 逐字段对照。
- 成熟证据：字段名与契约一致；现有 Fixture 能表达该状态，或缺口已列入数据缺口清单。
- 常见失分：用了契约里不存在的字段名；需要“同一用户的不同状态”却只有一个 Fixture；需要既有排程、既有用量等状态但 Fixture 结构里没有对应位置。

## 8. 可复现性

- 核验方式：找时间依赖、随机性、顺序依赖、外部状态依赖。
- 成熟证据：时间类用例有固定测试时钟；不依赖用例执行顺序；不依赖上一次运行的残留状态。
- 常见失分：结果随运行时刻变化（例如默认发送时刻早于当前时间时判定会漂移）；依赖已发送计数但没有初始化手段；用例之间共享可变状态。

## 9. 一致性与范围

- 核验方式：跨文档比对范围口径，检查产物内部是否自相矛盾。
- 成熟证据：范围与 PRD 13.1、测试方案分层一致；同一条规则只有一处表述。
- 常见失分：产物里的范围比 PRD 大或小；同一规则在两处表述不一致；历史版本残留的“待确认”与新版本的“已确认”并存，导致事实源不明；编号被回收或重复。

## 10. 风险与不可测项登记

- 核验方式：把每条找不到观测手段的结论收集起来，看有没有被静默省略。
- 成熟证据：不可测项集中登记，写明原因与承接方式（单测、库表断言、渠道桩、后续专项）。
- 常见失分：测不到的部分直接从产物里删掉而不登记；用“已由其他层覆盖”一句话代替具体承接方式；性能与回归维度留空。

## 级别判定

| 级别 | 判定标准 |
| --- | --- |
| 阻塞 | 错引用；覆盖缺口；不可构造的前置条件；不可判定的预期结果；越权优先级；未登记的不可测项；摘要或结论与内容矛盾 |
| 建议 | 表述、归类、可读性、编号组织；可合并的重复用例；格式不统一 |
| 待裁定 | 口径冲突；文档自身矛盾；不可测项是否接受；范围是否扩大；优先级争议 |

级别不得通胀：拿不出证据的怀疑不写进意见，写入“待确认”并由用户决定是否升级。
