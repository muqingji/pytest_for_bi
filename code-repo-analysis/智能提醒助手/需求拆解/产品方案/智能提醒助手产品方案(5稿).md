# 智能提醒助手产品方案 5 稿

> 文档定位：产品方案的评审汇总稿。  
> 来源：产品方案.md。  
> 后续：本稿确认后，扩展生成智能提醒助手 PRD（9 稿）。

## 1. 一句话定义

面向当天有未完成任务的被动型学生，在其更可能学习的时间发送一次受频控和免打扰保护的提醒，提升 Push 打开率并带来可归因的任务完成增量。

## 2. 业务目标与产品贡献

### 2.1 整体业务目标

- 整体任务完成率从当前 60% 提升至 75%。
- Push 打开率从当前约 8% 提升至 15% 以上。
- 在提升打开率的同时控制重复提醒和用户打扰。

### 2.2 智能提醒的贡献目标

智能提醒不是完成整体业务目标的唯一手段。本产品需要通过线上对照实验，验证在符合提醒条件的目标用户中，相比固定时间提醒或不提醒，智能提醒对 Push 打开率和任务完成率带来的可归因增量。

## 3. 目标用户

| 用户类型 | 产品处理 |
| --- | --- |
| 自驱型 | 已完成不提醒；未完成时最多低打扰提醒 |
| 被动型 | 首期重点服务，按活跃习惯和任务截止时间提醒 |
| 流失型 | 不通过增加提醒频次解决，后续进入独立召回策略 |

## 4. 核心用户流程

~~~text
打开 App
→ 查看今日任务和完成进度
→ 查看或调整提醒设置
→ 在合适时间收到提醒
→ 点击提醒进入今日任务
→ 开始学习
→ 完成任务
~~~

## 5. 核心产品规则

### 5.1 提醒资格

系统每天评估提醒资格，但只有同时满足以下条件才发送：

- 当日存在未完成必做任务。
- 用户没有关闭智能提醒。
- 当前日期和任务仍然有效。
- 当天没有达到提醒上限。
- 当前或延后时间不违反免打扰设置。

周中、周末或节假日都可能存在当日任务；没有任务或休息日不发送提醒。

### 5.2 提醒时间

优先参考：

1. 用户最近常完成任务的时间段。
2. 用户最近常打开 App 的时间段。
3. 默认活跃时段 16:00–18:00 和 19:00–21:00。
4. 任务截止时间前的最后可用窗口。

### 5.3 渠道和频控

- 每位学生每天最多接收 1 次 Push。
- 用户点击提醒但未完成任务时，当天不立即重复发送。
- 用户选择延后时，只在当天剩余可用时间内重新安排。
- Push 权限关闭时使用站内提醒；站内提醒不可用时记录不可发送状态。
- 任务完成后停止当天剩余的未完成提醒。

### 5.4 提醒内容

首期使用结构化模板：

~~~text
标题：今天还有 {remaining_count} 项学习任务
正文：预计用时 {estimated_minutes} 分钟，现在开始刚刚好
按钮：去完成任务
~~~

内容必须反映最新任务状态，不使用恐吓、羞辱或制造焦虑的表达，使用鼓励、激励的语气表达。

## 6. MVP 产品需求候选

| 产品需求 | 初始优先级 | 进入原因 |
| --- | --- | --- |
| 今日任务状态和完成入口 | MUST | 学生理解提醒并完成任务的基础 |
| 用户提醒开关 | MUST | 用户控制提醒的基础能力 |
| 免打扰设置 | MUST | 核心打扰控制能力 |
| 被动型用户的个性化提醒时间 | MUST | 直接验证核心假设 |
| 已完成任务不提醒 | MUST | 避免明显错误和无效打扰 |
| 每日提醒上限 | MUST | 产品频控约束 |
| Push 关闭后的站内提醒降级 | SHOULD | 覆盖权限关闭场景，可先做简单版本 |
| 稍后提醒 | SHOULD | 提升控制感，但会增加策略复杂度 |
| 当前提醒记录查看 | SHOULD | 方便用户理解提醒历史 |
| 流失型用户召回策略 | V2 | 不是首期核心人群 |
| 真实 Push 厂商配置 | V2 | 依赖外部系统 |
| 完整后台管理平台 | OUT | 不属于学生提醒核心体验 |

## 7. MVP 冻结规则

在进入 9 稿 PRD 前，逐项确认最终状态：

| 标记 | 含义 |
| --- | --- |
| MUST | 本期必须实现并进入验收 |
| SHOULD | 评审后选择性进入本期 |
| V2 | 本期不实现，保留后续规划 |
| OUT | 排除在本题范围之外 |

测试用户、测试数据、模拟时间、Mock 发送、自动化测试和技术契约不属于本稿的产品需求，分别见测试方案和技术方案。（本条是留给 AI 看的）

## 8. 评审待确认事项

1. 是否确认首期只重点服务被动型学生？ --回复：是
2. 每位学生每天最多 1 次 Push 是否作为正式规则？--回复：是
3. Push 关闭时是否实现简单站内提醒？--回复：是，需要给轻量化提醒，文案需简短（AI给出文案）。
4. 用户是否可以编辑提醒开关和免打扰时间？--回复：是，编辑提醒开关与第三条确认项重复，免打扰时间存储需要入库，需要关注修改后的生效范围修改后立即生效。
5. 是否保留“稍后提醒”？--回复：是，稍后提醒功能需要简化操作步骤，点击后默认一小时后提醒，不需要用户设置稍后提醒的时间间隔。
6. 任务完成定义是否为完成全部必做任务？--回复：是，必须任务都完成，所以算完成任务，未进入任务详情、未做完（不关注题目对错，只关注任务是否完成）都算作未完成，未完成的场景由 AI在 9 稿中补全
