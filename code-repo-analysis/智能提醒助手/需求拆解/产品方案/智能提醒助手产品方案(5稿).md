# 智能提醒助手产品方案 5 稿

> 文档定位：产品方案的评审汇总稿。  
> 来源：产品方案.md。  
> 后续：本稿确认后，扩展生成智能提醒助手 PRD（9 稿）。

## 1. 一句话定义
面向当天有未完成任务的被动型学生，以及流失后重新打开 App 的回流型学生，在其更可能学习的时间发送一次受频控和免打扰保护的提醒，提升 Push 打开率并带来可归因的任务完成增量。

## 2. 业务目标与产品贡献

### 2.1 整体业务目标

- 整体任务完成率从当前 60% 提升至 75%。
- Push 打开率从当前约 8% 提升至 15% 以上。
- 在提升打开率的同时控制重复提醒和用户打扰。

### 2.2 智能提醒的贡献目标

智能提醒不是完成整体业务目标的唯一手段。本产品需要通过线上对照实验，验证在符合提醒条件的目标用户中，相比固定时间提醒或不提醒，智能提醒对 Push 打开率和任务完成率带来的可归因增量。

## 3. 目标用户

| 用户类型 | 产品处理 |
| --- | --- |
| 自驱型 | 已完成不提醒；未完成时最多低打扰提醒 |
| 被动型 | 本期 P0 重点服务，按活跃习惯和任务截止时间提醒 |
| 流失型 | 连续 3 天以上未打开 App；不进入主动 Push 排程，后续进入独立召回策略 |
| 回流型 | 本期 P0 服务人群；流失型重新打开 App 的当天，首日不发送提醒（避免与用户主动打开形成双重打扰），次日起恢复常规 Push；首日站内承接已移出 P0、列入 P1，具体判定窗口与阈值待确认 |

## 4. 核心用户流程

~~~text
打开 App
→ 查看今日任务和完成进度
→ 查看或调整提醒设置
→ 在合适时间收到提醒
→ 点击提醒进入今日任务
→ 开始学习
→ 完成任务
~~~

## 5. 核心产品规则

### 5.1 提醒资格

系统每天评估提醒资格，但只有同时满足以下条件才发送：

- 当日存在未完成必做任务。
- 用户没有关闭智能提醒。
- 当前日期和任务仍然有效。
- 当天没有达到提醒上限。
- 当前或延后时间不违反免打扰设置。

周中、周末或节假日都可能存在当日任务；没有任务或休息日不发送提醒。

### 5.2 提醒时间

优先参考：

1. 用户最近常完成任务的时间段。
2. 用户最近常打开 App 的时间段。
3. 默认活跃时段 16:00–18:00 和 19:00–21:00。
4. 任务截止时间前的最后可用窗口。

### 5.3 渠道和频控

- 每位学生每天最多接收 1 次系统主动 Push；用户主动触发的“稍后提醒”不计入该上限（兼容处理见 6.1）。据此每天最多 2 次 Push：1 次系统主动提醒 + 最多 1 次用户主动延后提醒。
- 用户点击提醒但未完成任务时，当天不立即重复发送。
- 用户选择延后时，只在当天剩余可用时间内重新安排，一小时后通过 Push 再次提醒。
- 延后提醒产生的这次 Push 不再提供“稍后提醒”入口，不展示该按钮；延后链条最多一段，避免当天被反复延后。
- 用户未授权系统 Push，或 Push 发送失败时，不调用 Push，跳过本次提醒并记录未触达原因；站内提醒承接不在本期 P0 范围，列入 P1。
- 任务完成后停止当天剩余的未完成提醒。
- 本期 P0 只使用 Push 单渠道，不做渠道编排；Push 与站内的重复触达控制随站内承接一并归入 P1。

### 5.4 提醒内容

首期使用结构化模板：

~~~text
标题：今天还有 {remaining_count} 项学习任务
正文：预计用时 {estimated_minutes} 分钟，现在开始刚刚好
按钮：去完成任务
~~~

内容必须反映最新任务状态，不使用恐吓、羞辱或制造焦虑的表达，使用鼓励、激励的语气表达。

## 7. MVP 冻结规则

在进入 9 稿 PRD 前，以 P0/P1/P2 作为唯一的产品优先级：

| 标记 | 含义 |
| --- | --- |
| P0 | 本期 MVP 必须实现并进入验收 |
| P1 | P0 完成后再实现，不阻塞 MVP 准出 |
| P2 | 后续规划或本题不实现，不进入本期验收 |

本题 MVP 范围为全部 P0 项。测试用户、测试数据、模拟时间、Mock 发送、自动化测试和技术契约不属于本稿的产品需求，分别见测试方案和技术方案。

任务系统、任务完成统计、任务入口和 Push 基础能力属于题目背景中的既有能力。本题不新建任务详情页、做题流程、任务完成统计或 Push 基础设施；这些能力只作为智能提醒服务的外部输入和调用出口。

### 7.1 既有能力与外部依赖

以下能力由现有 App 或业务服务提供，不属于本题新增功能，也不参与 P0/P1/P2 优先级排序：

- 每日学习任务及必做任务定义。
- 任务完成状态和每日任务完成率统计。
- 任务详情页、做题流程和任务完成回传。
- 既有 Push 通道及发送基础设施。
- 提醒点击后的任务入口或 Deep Link。

本题只消费任务状态和任务入口，并在现有 Push 能力之上实现提醒资格判断、时机选择、频控、免打扰和延后提醒。

站内提醒展示能力虽属既有能力，但不再作为 P0 依赖接入：P0 不调用、不设计、不验收站内渠道。Push 未成功触达时的站内承接与回流首日的站内承接列入 P1，P0 对应场景的处理见 6.1。

### 7.2 P2 激励召回规划

针对连续多日未完成任务、常规提醒效果有限的用户，后续可增加独立的激励召回机制，但不通过提高 Push 频次解决流失问题，也不属于本期 MVP。

- 首选“任务成就 + 积分权益”：按完成任务、连续完成和回流完成发放积分或勋章，优先兑换平台内权益，并设置每日上限。
- 排行榜只作为可选增强，优先采用用户主动参与的好友榜或同阶段榜，不做默认公开的全量排名。
- 实物激励暂不作为首版方案，待虚拟权益验证有效后，再评估预算、库存、配送、合规和作弊成本。

后续通过小流量对照实验评估回流率、任务完成率、留存、作弊、投诉和激励成本，不纳入本期验收。

## 8. 已确认产品决策

以下决策作为本次 MVP 的冻结输入：

1. 本期 P0 重点服务当天有未完成任务的被动型学生，以及流失后重新打开 App 的回流型学生；回流首日不发送提醒，次日起恢复常规 Push，具体判定窗口与阈值待确认。
2. 每位学生每天最多接收 1 次系统主动 Push；用户主动触发的“稍后提醒”不计入该上限。据此每天最多 2 次 Push：1 次系统主动提醒 + 最多 1 次用户主动延后提醒。
3. 用户未授权系统 Push，或 Push 发送失败时，不调用 Push，跳过本次提醒并记录未触达原因；站内提醒承接移出 P0，列入 P1。
4. 用户可以编辑提醒开关和免打扰时间，修改后立即影响后续提醒决策，免打扰设置需要持久化。
5. 保留“稍后提醒”，操作固定为点击后 1 小时后再次提醒，不开放时间间隔配置；渠道为 Push，且延后提醒产生的 Push 不再提供“稍后提醒”入口。
6. 完成全部必做任务才算当天完成；未进入任务详情或未完成全部必做任务均视为未完成，不关注题目对错。
7. 站内提醒及其承接逻辑（Push 未成功触达、回流首日）本次不纳入 P0，统一列入 P1；P0 为 Push 单渠道闭环，对既有 P0 逻辑的兼容处理见 6.1。
