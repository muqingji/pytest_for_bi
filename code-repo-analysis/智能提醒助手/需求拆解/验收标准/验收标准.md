# 智能提醒助手验收标准

> 状态：9 稿 PRD 对齐版。稍后提醒与每日 Push 上限的渠道关系仍待业务确认。

## 1. 决策规则

### AC-001：未完成任务的被动型用户生成提醒

~~~text
Given 用户属于被动型
And 今日仍有未完成任务
And 用户允许接收提醒
And 今日尚未达到提醒上限
When 系统生成提醒决策
Then should_remind = true
And 返回提醒时间、渠道、原因和策略版本
~~~

### AC-002：已完成任务不提醒

~~~text
Given 用户今日已经完成全部任务
When 系统生成决策或执行已排程提醒
Then 不生成新的未完成任务提醒
And 原因标记为 TASK_COMPLETED
~~~

### AC-003：免打扰时间延后

~~~text
Given 用户有未完成任务
And 当前时间处于免打扰区间
When 系统生成提醒决策
Then 不在当前时间发送
And 延后到下一个可用窗口，或返回不可提醒原因
~~~

### AC-004：Push 权限关闭时降级

~~~text
Given 用户有未完成任务
And 用户关闭 Push 权限
When 系统生成提醒决策
Then 不调用 Push 渠道
And 用户进入 App 后，站内提醒可用时在今日任务相关页面展示简短提醒
And 站内提醒不可用时跳过本次提醒并记录 NO_AVAILABLE_CHANNEL 原因
~~~

## 2. 频控与幂等

### AC-005：每日提醒频控

~~~text
Given 用户当天已经发送过一次 Push
When 系统再次执行调度
Then 不发送第二次 Push
And 返回 DAILY_CAP_REACHED
~~~

### AC-006：重复调度幂等

~~~text
Given 同一用户、日期和策略版本已经生成决策
When 调度任务重复执行
Then 不新增重复决策或发送记录
And 返回已有决策或幂等命中结果
~~~

### AC-007：发送失败重试

~~~text
Given 第一次发送失败
When 系统执行重试
Then 最多重试一次
And 重试使用相同 dedupe_key
And 不突破每日提醒上限
~~~

## 3. 时间和数据异常

### AC-008：缺少行为数据

~~~text
Given 用户没有足够的历史活跃数据
When 系统生成提醒决策
Then 使用默认活跃窗口
And 标记使用默认策略的原因
~~~

### AC-009：任务已过期

~~~text
Given 当前时间晚于任务截止时间
When 系统生成提醒决策
Then 不发送普通提醒
And 记录 TASK_EXPIRED
~~~

### AC-010：提醒前任务完成

~~~text
Given 用户已经生成排程提醒
And 用户在发送前完成全部任务
When 调度执行发送
Then 再次检查任务状态
And 取消发送
~~~

## 4. 事件记录

### AC-011：事件链路完整

~~~text
Given 系统生成并模拟发送一条提醒
When 用户打开提醒并完成任务
Then 记录决策、发送、打开、开始和完成事件
And 每个事件包含 decision_id 和 strategy_version
~~~

## 5. 设置、延后和内容

### AC-012：提醒设置立即生效

~~~text
Given 用户已经存在一条尚未发送的提醒排程
When 用户关闭智能提醒或修改免打扰时间
Then 后续提醒决策立即使用最新设置
And 已不再满足条件的排程被取消或延后
And 记录 reminder_preference_updated 事件
~~~

### AC-013：一小时后再提醒

~~~text
Given 用户当天仍有未完成必做任务
And 用户点击“稍后提醒”
When 系统处理延后操作
Then 生成一小时后的提醒排程
And 重新校验任务状态、免打扰时间、任务截止时间和每日频控
And 记录 reminder_snoozed 事件
~~~

> 已发送一次 Push 后，延后提醒是否允许再次使用 Push，待业务确认；实现不得突破每日 Push 上限。

### AC-014：提醒内容使用最新任务状态

~~~text
Given 用户存在未完成必做任务
When 系统生成 Push 或站内提醒内容
Then 内容展示最新剩余任务数量和预计用时
And 点击提醒后进入既有任务入口
And 不展示任务正文、成绩等敏感信息
~~~
