# 智能提醒助手验收标准

> 状态：9 稿 PRD 对齐版，含用户分层（流失 / 回流 / 自驱）验收项。P0 相关口径已确认：本期只使用 Push 单渠道；Push 未授权或发送失败时跳过本次提醒并记录未触达原因；延后提醒改用 Push 且不占用当日 1 次系统主动 Push 上限（同一用户同一天最多 2 次 Push），延后提醒不再提供再次入口；回流首日由 `AppOpened` 事件触发，当天不发送提醒、不生成 Push 排程，次日由每日评估恢复常规 Push 资格。站内提醒承接已随该需求移出 P0，不进入本期验收，见 AC-004 的边界说明。非 P0 事项见 PRD 13.1。

## 1. 决策规则

### AC-001：未完成任务的被动型用户生成提醒

~~~text
Given 用户属于被动型
And 今日仍有未完成任务
And 用户允许接收提醒
And 今日尚未达到提醒上限
When 系统生成提醒决策
Then should_remind = true
And 返回提醒时间、渠道、原因和策略版本
~~~

### AC-002：已完成任务不提醒

~~~text
Given 用户今日已经完成全部任务
When 系统生成决策或执行已排程提醒
Then 不生成新的未完成任务提醒
And 原因标记为 TASK_COMPLETED
~~~

### AC-003：免打扰时间延后

~~~text
Given 用户有未完成任务
And 当前时间处于免打扰区间
When 系统生成提醒决策
Then 不在当前时间发送
And 延后到下一个可用窗口，或返回不可提醒原因
~~~

### AC-004：Push 未成功触达后的站内承接（P1，不进入本期验收）

~~~text
Given 用户当天有未完成必做任务
And 用户当天未被 Push 成功触达（Push 未授权、发送失败、未生成 Push 排程或回流首日不出 Push）
And 用户当天进入 App 且当天尚未展示过站内提醒
When 系统执行提醒或用户进入今日任务相关页面
Then 不调用 Push 渠道
And 展示一次站内提醒并记录曝光事件和对应 decision_id
And 当天最多展示 1 次站内提醒，Push 已送达但未被点击时不展示
And 站内能力不可用时跳过本次提醒并记录 NO_AVAILABLE_CHANNEL
~~~

> P1 边界：站内提醒承接已随该需求移出 P0，本节不进入本期验收，待 P1 规划时细化；本期对 Push 未成功触达的要求见 AC-007。

## 2. 频控与幂等

### AC-005：每日系统主动 Push 频控

~~~text
Given 用户当天的 1 次系统主动 Push 已经发送
When 系统再次执行提醒调度
Then 不发送第二次系统主动 Push
And 返回 DAILY_CAP_REACHED
~~~

### AC-006：重复调度幂等

~~~text
Given 同一用户、日期和策略版本已经生成决策
When 调度任务重复执行
Then 不新增重复决策或发送记录
And 返回已有决策或幂等命中结果
~~~

### AC-007：Push 未授权或发送失败时的处理

~~~text
Given 用户 Push 未授权，或第一次发送明确失败
When 系统处理本次提醒发送
Then Push 未授权时不调用 Push 并跳过本次提醒
And 明确失败时最多重试一次且复用相同 dedupe_key
And 记录未触达原因，不在当天追加第二次触达
And 不突破每日系统主动 Push 上限
~~~

## 3. 时间和数据异常

### AC-008：缺少行为数据

~~~text
Given 用户可读取的历史行为天数少于 3 天
When 系统生成提醒决策
Then 按被动型处理并使用默认活跃窗口
And 原因码标记为 INSUFFICIENT_HISTORY
And 使用默认发送时刻 19:30，落在免打扰或晚于任务截止前 1 小时时回退到 17:00
~~~

### AC-009：任务已过期

~~~text
Given 当前时间晚于任务截止时间
When 系统生成提醒决策
Then 不发送普通提醒
And 记录 TASK_EXPIRED
~~~

### AC-010：提醒前任务完成

~~~text
Given 用户已经生成排程提醒
And 用户在发送前完成全部任务
When 调度执行发送
Then 再次检查任务状态
And 取消发送
~~~

## 4. 事件记录

### AC-011：事件链路完整

~~~text
Given 系统生成并模拟发送一条提醒
When 用户打开提醒并完成任务
Then 记录决策、发送、打开、开始和完成事件
And 每个事件包含 decision_id 和 strategy_version
~~~

## 5. 设置、延后和内容

### AC-012：提醒设置立即生效

~~~text
Given 用户已经存在一条尚未发送的提醒排程
When 用户关闭智能提醒或修改免打扰时间
Then 后续提醒决策立即使用最新设置
And 已不再满足条件的排程被取消或延后
And 记录 reminder_preference_updated 事件
~~~

### AC-013：稍后提醒改用 Push 且不占当日系统主动上限

~~~text
Given 用户当天仍有未完成必做任务
And 用户点击“稍后提醒”
When 系统处理延后操作
Then 生成一小时后的 Push 排程
And 重新校验任务状态、免打扰时间、任务截止时间和频控
And 该次 Push 不占用当日 1 次系统主动 Push 上限，同一用户同一天最多 2 次 Push
And 该排程不再提供“稍后提醒”入口，第二次 snooze 请求返回 INVALID_REQUEST
And 记录 reminder_snoozed 事件
~~~

### AC-014：提醒内容使用最新任务状态

~~~text
Given 用户存在未完成必做任务
When 系统生成 Push 提醒内容
Then 内容展示最新剩余任务数量和预计用时
And 点击提醒后进入既有任务入口
And 不展示任务正文、成绩等敏感信息
~~~

## 6. 用户分层判定

> 分层所需行为信号与判定顺序见 PRD 3.3 节。分层结果每天按行为数据现算，不落库为固定标签。

### AC-015：流失型用户不进入主动 Push 排程

~~~text
Given 用户在评估时点连续未打开 App 的天数大于或等于 3 天
When 系统生成提醒决策
Then should_remind = false
And 原因码标记为 USER_INACTIVE
And 不生成主动 Push 排程
~~~

### AC-016：流失用户重新打开 App 当天不发送提醒

~~~text
Given 用户触发 `AppOpened` 事件
And 本次打开 App 前，上一次打开 App 距今天的本地日期间隔（`days_since_last_open`）大于或等于 3 天
And 用户当天仍有未完成必做任务
When 系统处理 `AppOpened` 事件并生成提醒决策
Then 判定为回流型
And 当天不发送提醒、不生成 Push 排程
And 原因码标记为 RETURNING_FIRST_DAY，不沿用前一天的 USER_INACTIVE 拦截结果
And 次日由每日评估重新校验任务、设置、免打扰和频控后，恢复常规 Push 资格
~~~

### AC-017：自驱型用户按信号组合控制打扰

~~~text
Given 用户最近 7 天完成全部必做任务的天数大于或等于 5 天
And 其中收到提醒后完成的天数小于或等于 1 天
When 系统生成提醒决策
Then 当天任务已完成时不生成提醒
And 当天任务未完成时最多生成一次低打扰提醒
~~~

### AC-018：用户关闭提醒后不生成提醒

~~~text
Given 用户已关闭智能提醒
When 系统生成提醒决策或执行已排程提醒
Then should_remind = false
And 原因码标记为 REMINDER_DISABLED
And 取消当天尚未发送的排程
~~~

## 7. 不进入本期验收的边界

- 站内提醒承接：随站内提醒需求移出 P0，本期不实现、不验收，AC-004 仅作为边界记录保留，待 P1 规划时细化。
- 提醒记录查看、流失型召回、运营后台与激励召回：属后续范围，不进入本期验收，边界见 PRD 13.1。
