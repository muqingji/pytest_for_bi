## 决策与阻塞项

- 未解决事项：真实 Push 能力、调度平台与事件总线需接入时核验；`UNKNOWN` 状态交由 reconcile 收敛，本轮不实现 reconcile；snooze 用量计数与「当天最多 2 次 Push」校验随 FR-007 实现。
- 需要人工确认：无。本轮 5 项契约缺口已由用户逐项确认（1-A、2-B、3-A、4-A、5-A）。
- 人工确认结果：投递写入端口用 `UpdateDeliveryStatus`；渠道幂等键 = `{user_id}_{task_date}_{channel}_{decision_id}_{schedule_version}`，重试复用；本轮只固定 `schedule_type=INITIAL` 用量口径并登记 `SNOOZE` 类型与索引；补 `ContentRenderer` 端口并用占位实现跑通发送链路；dispatch 读偏好判定 Push 可用性，任务状态二次校验仍归 FR-004。
- 已知限制：本地 `MockPushSender` 不代表真实 Push 能力；文案为空占位（FR-008 落地）；HTTP `transport/http` 未实现，因此 `tests/cases/dispatch_due.json` 的 DISP-008/009/010 仍为 pending；`feature_enabled` 总开关未接线。
