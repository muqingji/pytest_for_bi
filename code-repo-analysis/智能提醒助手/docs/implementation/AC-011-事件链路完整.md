## 决策与阻塞项

- 未解决事项：**1 项观察项，不阻塞本轮准出**——评估复用既有决策行时，`Evaluate` 返回的 `decision_id` 是引擎按 `dedupe_key` 推导的 ID，与持久化行 ID 不同，事件挂在持久化 ID 下。触发条件为「既有行 ID 与推导 ID 不一致」，本地正常生产路径不会构造这种数据。
- 需要人工确认：0 项（本轮范围与责任边界已由用户 2026-09-21 选定方案 A 确认）。
- 人工确认结果：2026-09-21 用户选定**方案 A**——把 AC-011 登记为横切验收项并划清「事件产生方」责任边界：本服务负责决策、发送、失败、取消、延后、设置变更事件且全部携带 `decision_id`、`strategy_version`；打开、开始、完成事件由既有 App 与任务系统提供；验收方式为模块集成测试 + 库表断言，不新增事件查询接口。
- 已知限制：①事件发布失败由 outbox/reconcile 补发的能力本地未实现，故"发布失败后补发"未验证；②既有系统侧事件的关联键由外部系统提供，本地只断言契约，不声明已验证；③同一时刻的并列事件（如决策与取消）按写入顺序判定先后，时间戳相同不构成倒序。
