## 决策与阻塞项

- 未解决事项：真实任务服务读取超时口径与生产事件总线待接入时核验；`UNKNOWN` 交 reconcile 收敛，本轮不实现 reconcile；Snooze 入口与 SNOOZE 用量计数随 FR-007。
- 需要人工确认：无（D1/D2/D3 已由用户逐项选择方案 A；其余为已登记契约的直接实现）。
- 人工确认结果：D1-A 评估拒绝时取消未发送排程并保留 CANCELLED 行、逐条发 `reminder_cancelled`，重新排期改为同一 `(decision_id, schedule_version)` 条件更新替换；D2-A 发送链路新增 `TaskRepository` 依赖、发送前读快照、装配 `TemplateRenderer` 并把 `Actions` 映射进 `PushRequest`；D3-A 任务服务不可用不新增状态，释放抢占回 `SCHEDULED` 由下一次调度重试。
- 决策派生项（无新增产品规则）：①关闭提醒路径（FR-003）改为复用同一「取消 + 逐条事件」能力，因此该路径开始产生 `reminder_cancelled`，与 IDL 中 `reminder_cancelled` 的产生场景一致；②`CreateDecisionAndSchedule` 不再物理删除历史行，替换为条件更新，唯一键冲突仍按既有冲突处理回读已有决策；③接上真实渲染器后按 4.3.2.2 落地「文案校验失败 -> `CONTENT_INVALID`、不重试、`failed` +1」，避免渲染失败被当成依赖错误导致下一批次无限重试。
- 依赖错误指标口径：本地不接入监控平台（技术方案 6.1），任务快照读取失败按「释放抢占 + 返回错误」处理，依赖错误以应用层错误返回并由 CLI/调用方的结构化输出承接，`sent` 不增加；生产告警指标随接入时配置。
- 已知限制：`EstimatedMinutes` 缺失或快照缺失时按 `CONTENT_INVALID` 拒绝发送（`FAILED`，不重试），需要上游任务系统补齐字段；真实渠道长度限制与 Deep Link 格式仍为生产接入核验项。
- 待确认（不影响本轮准出）：`adapter/channel` 的 `PlaceholderRenderer` 是 FR-005 阶段的临时替身，本轮装配已换成 `TemplateRenderer`，该类型目前只被自身单测引用；是否删除属既有代码清理，未在本轮处理。
