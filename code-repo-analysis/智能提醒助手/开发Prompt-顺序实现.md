# 智能提醒助手：顺序开发 Prompt

## 使用方式

每次只复制“通用开发约束”以及一个“本轮任务”段落给 Codex。完成并验收一个 FR 后，再复制下一个 FR。不要一次把多个 FR 交给同一个 AI 实现。

推荐顺序：

`FR-002 -> FR-003 -> FR-005 -> FR-008 -> FR-004 -> FR-007`

FR-001 已完成；FR-006、FR-009 属于 P1，本轮不实现。

---

## 通用开发约束

你是本项目的后端实现代理。本轮只实现下面“本轮任务”中指定的一个 FR 和它列出的 AC。

必须完整阅读并遵守：

`dev-tools/skills/tech-design-implementation/SKILL.md`

权威输入文件为：

1. `智能提醒助手PRD(9稿).md`
2. `技术方案/技术方案.md`
3. `需求拆解/验收标准/验收标准.md`
4. `测试方案/测试方案.md`
5. 测试数据构造说明
6. 技术方案第 3.4 节模块划分
7. 技术方案第 9 章未决项
8. 当前功能相关的现有代码、测试、迁移和未提交修改
9. `docs/implementation/` 下已有进度记录
10. `AI_USAGE.md`

### 开始编码前

先执行并记录：

- `git status --short`
- `git diff --check`
- 已有基线测试

然后阅读本功能在 PRD、AC、技术方案和 3.4 模块表中的全部内容，输出本轮范围锁定表：

- FR、AC 和正式名称；
- PRD 行为和拒绝路径；
- 技术方案章节；
- 3.4 模块的职责、入口、主要落点、异常边界；
- 计划修改的代码、测试、迁移和配置文件；
- 不在本轮范围内的内容；
- 第 9 章未决项是否阻塞本轮。

在范围锁定表完成前不要写代码。

### 人工确认门禁

遇到以下任一情况必须停止，不得猜测、不得先写代码：

- PRD、AC、技术方案存在冲突；
- AC 没有对应的技术契约；
- 文档未定义字段、状态、接口、默认值、重试、表结构、索引或错误语义；
- 需要新增技术方案 3.4 未登记的模块或代码位置；
- 技术方案第 9 章未决项阻塞本轮；
- 当前未提交修改与本轮文件重叠且意图不清楚；
- 需要选择多个文档没有明确的合理方案。

停止时必须报告：证据、受影响的 FR/AC、影响、候选方案、推荐方案、需要我作出的确切决定，以及需要回写的文档。用户确认前不得继续。

### 实现边界

- 只实现本轮指定 FR；不得顺手实现其他 FR、P1、P2 或待确认事项。
- 不得修改 PRD、验收标准或技术方案来迁就代码。
- 不得臆造新的产品策略、默认值、状态、接口、字段、表、索引或外部服务能力。
- 不得做无关重构或清理。
- 不得删除现有代码，除非有文档证据证明它超出本轮范围，并先向我报告。
- 保持领域层 -> 应用层 -> 端口层 -> 适配器层的依赖方向。
- 业务规则不能放在 Handler、Repository、Mock 或传输层。
- Mock、Fixture 和 Demo 数据不能替代生产持久化设计。
- 不得覆盖或撤销用户已有的无关修改。

### 测试硬门禁

必须补充本轮功能的正常、边界、失败、空数据、未知状态、重复请求、幂等和必要并发场景测试，并逐条覆盖本轮 AC。

必须实际执行并记录：

```bash
go test -count=1 ./...
go test -race ./...
go vet ./...
go build ./...
go test -covermode=atomic -coverprofile=/tmp/<FR编号>.cover ./...
go tool cover -func=/tmp/<FR编号>.cover
```

本轮新增和修改代码的单测语句覆盖率必须为 100%。本轮涉及的模块集成测试必须全部通过，不允许失败、跳过或忽略。

随后执行符合项目约定的 Mock 联调或真实联调，并明确标注联调类型。没有实际执行的检查不得声称已完成。

### 双文档回查和留档

实现后重新逐项核对 PRD、AC 和技术方案，确认没有超范围或语义偏差。执行：

```bash
python3 dev-tools/skills/prd-to-tech-design/scripts/check_tech_design.py \
  --design 技术方案/技术方案.md \
  --prd 智能提醒助手PRD(9稿).md \
  --prd 需求拆解/验收标准/验收标准.md

python3 dev-tools/skills/prd-to-acceptance-criteria/scripts/check_acceptance_criteria.py \
  --ac 需求拆解/验收标准/验收标准.md \
  --prd 智能提醒助手PRD(9稿).md
```

按 `dev-tools/skills/tech-design-implementation/references/feature-progress-template.md` 更新：

`docs/implementation/<FR编号>-<功能名称>.md`

记录 FR/AC 追踪、修改文件、迁移、测试命令和实际结果、覆盖率、集成测试、联调、双文档回查和未解决事项。出现人工决策时更新 `AI_USAGE.md`。

只有代码、迁移、单测、覆盖率、集成测试、联调、回归测试、双文档回查和进度留档全部完成，且不存在未确认阻塞项，才能报告本轮完成。

### 最终汇报格式

只汇报：

1. 实际实现的 FR 和 AC；
2. 修改、新增和未修改的文件；
3. 实际执行的命令和结果；
4. 单测覆盖率和未覆盖位置；
5. 集成测试通过/失败/跳过数量；
6. 联调类型和结果；
7. PRD、AC、技术方案回查结果；
8. 未解决事项和人工确认项；
9. 是否满足准出门禁。
