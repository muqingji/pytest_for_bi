# AI 协作说明

> 本文记录 AI 在本项目中的参与边界、人工决策和验证方式。随着项目继续开发，需要持续补充。

## 1. AI 参与的工作

当前 AI 参与了以下工作：

- 阅读和整理题目背景、交付要求及评审标准。
- 识别任务完成率与 Push 到达率的指标口径差异。
- 对产品方案进行结构化拆解。
- 补充用户分层、提醒规则、频控、免打扰、幂等和异常场景。
- 生成留档目录和交付物组织建议。
- 协助检查文档之间的范围和交付关系。

后续编码阶段可补充：

- 代码草拟和重构建议。
- 单元测试场景生成。
- 代码审查和边界条件检查。
- README 与测试报告整理。

## 2. 人工负责的判断

以下判断需要由候选人确认并对最终结果负责：

- 任务完成率的统计口径和 60% 的推导假设。
- 首期重点服务被动型学生。
- MVP 做什么、不做什么。
- 每日提醒上限、免打扰和流失用户策略。
- 是否引入站内提醒（已确认：本期不做 P0、列入 P1）、“稍后提醒”（已确认：保留 P0、改用 Push）和低频召回。
- 最终技术栈、数据模型和交付范围。

AI 提供的是分析、候选方案和检查意见，不替代产品取舍和最终验收。

## 3. 验证方式

- 用题目中的 30 万、12 万和 40% 数据重新核算任务完成率。
- 将核心产品规则转换为 Given/When/Then 验收场景。
- 使用自动化测试验证决策引擎、频控、免打扰和幂等。
- 使用预置用户场景进行端到端 Demo。
- 通过全新环境安装、启动和测试检查最终交付。
