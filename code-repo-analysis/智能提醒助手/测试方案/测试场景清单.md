# 智能提醒助手测试场景清单

> 状态：待审批（门禁 A）
> 版本：v0.1
> 生成方式：test-case-design 阶段一
> 范围：本期 P0（FR-001~FR-005、FR-007、FR-008）；FR-006 站内提醒、FR-009 提醒记录查看属 P1，不进入本期
> 事实源：`智能提醒助手PRD(9稿).md`、`需求拆解/验收标准/验收标准.md`、`技术方案/技术方案.md`、`docs/api/reminder-service.openapi.yaml`

## 1. 推导说明

- 场景来源只有四类：验收标准的 AC、PRD 的规则与判定顺序、技术方案的异常与降级链路、IDL 的契约约束。
- 引用格式为 `文件:行号`，行号指向规定本身；脚本会校验文件存在且行号未越界。
- 19:30、17:00、21:30–07:00、流失 3 天、自驱型 5 天/7 天、提醒归因 1 天均为 MVP 设计假设（见 PRD:688），场景里按当前配置描述，不表述为题目事实。
- 场景类型分五类：正常、异常、边界为骨架（必做且必须做等价类划分），性能与回归本期简化或跳过。

## 2. 正常场景

### SC-001 被动型用户当天有未完成任务时生成 Push 排程
- 优先级：P0
- 来源：code-repo-analysis/智能提醒助手/智能提醒助手PRD(9稿).md:301、code-repo-analysis/智能提醒助手/智能提醒助手PRD(9稿).md:288、code-repo-analysis/智能提醒助手/需求拆解/验收标准/验收标准.md:9
- 关联需求：AC-001、FR-001、FR-002
- 场景类型：正常场景
- 等价类：
  - 有效等价类：任务未完成且在截止时间前、提醒已开启、Push 已授权、当日未达上限、历史行为天数大于等于 3
  - 无效等价类：无任务 / 任务已完成 / 任务已过期 / 提醒已关闭 / Push 未授权 / 已达上限 / 历史行为不足 3 天
  - 边界值：截止时间等于当前时间、当日用量等于上限、历史行为天数等于 3
- 覆盖维度：正常主路径、前置不满足、频控上限
- 判定点：should_remind=true；channel=push；reason_code=ELIGIBLE；生成一条 SCHEDULED 排程
- 优先理由：P0 需求主路径，对应 MVP-001

- 场景类型：正常场景
- 等价类：
  - 有效等价类：历史行为天数 0、1、2 天且任务未完成
  - 无效等价类：无任务 / 任务已完成 / 任务已过期
  - 边界值：历史行为天数 0、2、3

- 判定点：reason_code=INSUFFICIENT_HISTORY；scheduled_at 取用户本地 19:30；19:30 不可用时回退 17:00

### SC-003 自驱型用户当天未完成时生成最多一条系统主动 Push

- 等价类：
  - 有效等价类：complete_days_7d 大于等于 5 且 reminder_attributed_complete_days_7d 小于等于 1，且当天任务未完成
  - 无效等价类：complete_days_7d 小于 5 / reminder_attributed_complete_days_7d 大于 1 / 当天任务已完成
  - 边界值：complete_days_7d 等于 5、reminder_attributed_complete_days_7d 等于 1

### SC-008 提醒设置缺失或读取失败时的处理
