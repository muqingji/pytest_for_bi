# BI 标准输出契约

排查输出统一包含以下 4 段；若信息不足，先给 `missing_info`：

```markdown
### 1. 路由判断
- chosen_route:
- why_now:
- alternatives_ruled_out:
- handoff_needed:

### 2. 排查结论

按模块类别收口（二选一收口仅限产品口径类）：

- **产品口径类**（权限/对数/字段/目标/导出/订阅）——必须二选一：
  - `排查结论：设计如此`（FAQ 互殴 / 未过缓存窗口 / 产品口径如此）
  - `排查结论：需要研发处理`
- **运维性能类**（同步延迟/慢查询/聚合/拼表/渲染）——三选一：
  - `排查结论：需要研发处理`
  - `排查结论：需要基础设施或运维处理`（如 MQ 扩容、CH 资源/分区优化）
  - `排查结论：已定位，建议动作如下`（当段给出动作清单）

按同步链路、查询链路或产品口径说明已锁定的根因。

### 3. 证据链
* 关键 traceId / 报表 ID / 时间点
* 源数据 vs 仓库数据对比快照
* CH 慢查询 SQL + 耗时 + 扫描行数
* copier 同步日志 / MQ 消费 lag 截图

### 4. 建议动作
给出下一步可执行动作；若仍缺证据，明确下一跳技能和补查点。
```
