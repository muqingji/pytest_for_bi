# subscription：BI 订阅/转发/推送排查

```yaml
symptom: 报表订阅不推送 / 推送空白 / 推送数据与报表不一致 / 部分用户收不到 / 转发后数据不更新
inputs:
 required: [tenant_id, occurred_time]
 optional: [subscription_id, report_id, user_id, push_time]
outputs:
 signals: [push_record_exists, snapshot_has_data, receiver_permission, cache_status, timezone_offset]
next_skills: [fx-ops-query, fx-ops-tracing, fx-ops-monitoring]
escalate_when:
 - 大面积订阅不推送（调度级故障）→ 回抛 fx-ops 升级为 S2
 - 订阅推送数据泄露（非授权用户收到敏感数据）→ 立即回抛 fx-ops 升级为 S1
 - 当天改点、次日仍不按新时间推 → 才查调度，不要当天当故障
```

当天改订阅次日才生效、实时订阅不支持图表人员变量，都是产品行为。结论只能写 `排查结论：设计如此` 或 `排查结论：需要研发处理`。

## Step 0：产品口径门禁（先于调度/导出）

### 0.1 当天新建或修改订阅，第二天生效

订阅任务凌晨已备好。当天改推送时间，**当日仍按旧点推，次日才按新点**。这是 `设计如此`，不是调度中断（不要直接套模式 A）。

次日仍不按新时间推，再进 Step 2。

### 0.2 离线订阅 vs 实时订阅

- 离线订阅（老快照文件）**支持**图表人员变量
- 实时订阅（图表实时查询）**不支持**图表人员变量
- 「按图表人员变量推送，普通员工有负责数据却没收到」：先确认是不是实时订阅；是则 `设计如此`

### 0.3 推送空白先过权限

订阅导出常以特定身份执行。没图/没数/没导出权限时会空白或只有表头，先转 `permission-issue.md` Step 0，不要先当 ExcelReportExport NPE。

## 排查步骤

### Step 1：确认 web 端报表是否正常

先排除数据源问题：
1. 用管理员账号在 web 端打开报表，确认数据是否正常
2. 如果 web 端也无数据 → 先走 sync-delay.md 或 data-consistency.md

### Step 2：检查推送记录

查推送记录表，确认定时任务是否执行：
- 推送记录是否存在
- 推送时间是否正确
- 推送状态（成功/失败/跳过）

如果无推送记录 → **定时任务调度异常**（检查调度服务状态、配置文件是否正常加载）。

### Step 3：检查推送内容

推送记录存在但用户反馈问题时：

| 问题 | 排查方向 |
| --- | --- |
| 推送空白/只有表头 | 快照导出异常（检查 ExcelReportExport 日志是否有 NPE） |
| 数据与报表不一致 | 快照时间窗口偏差（检查时区、日期计算） |
| 部分用户收不到 | 权限问题（检查接收人的报表查看权限、企信空间是否满） |

### Step 4：检查缓存问题（转发场景）

转发报表后数据不更新或显示异常时：
1. 检查预计算缓存是否失效
2. 检查查询缓存是否刷新
3. 检查小程序/PC 客户端缓存是否清理

## 线上高频模式（来自 Bug 归纳）

### 模式 A：订阅推送未送达（最高频）

已设置定时订阅但到时间没有收到推送，或修改推送时间后不生效。

**先过 Step 0.1**：当天改点，当日仍按旧点、次日才生效 → `设计如此`，不要当调度异常。

**根因**（仅次日仍不生效，或大面积没推送记录时）：定时任务调度异常，包括配置文件变更导致调度中断、任务堆积。
**排查**：
1. 查推送记录表确认是否有推送记录
2. 查调度服务日志，确认定时任务是否执行
3. 如果近期有配置变更，确认调度是否恢复
**修复**：恢复调度服务，手动补推缺失的报表。

### 模式 B：订阅报表推送空白

CRM 报表查看有数据，但推送后打开显示空白或只有表头。

**根因**：
- 订阅导出时以特定身份执行，该身份无数据权限 → 导出空数据
- ExcelReportExport 构造过程中 NPE（定时储存导出异常）
- 手机端渲染兼容性问题（华为/安卓机型）

**排查**：
1. 确认 web 端报表直接查看是否有数据
2. 确认是手机端空白还是 web 端也空白
3. 如果后台日志有 ExcelReportExport NPE → 导出构造失败
4. 如果只是手机端空白 → 客户端兼容性问题

### 模式 C：推送数据日期偏移

推送的数据日期与预期不符（如"昨天"变成了"前天"）。

**根因**：快照时间窗口与时区/日期计算偏差。订阅生成快照时取数的时间基准与用户预期不一致（"昨天"在服务端解释为 UTC 时间的前一天）。
**排查**：
1. 确认用户的时区设置
2. 确认订阅中相对时间（"昨天/上周/上月"）的计算基准
3. 对比服务端时间与用户本地时间
**修复**：统一使用用户时区而非服务端时区计算相对时间。

### 模式 D：部分用户收不到推送

订阅范围内部分员工收不到，其他人正常。

**根因**：
- 接收人缺少报表查看者权限
- 推送目标解析失败（部分用户 ID 异常）
- 企信空间满

**排查**：
1. 确认收不到推送的用户是否有报表查看权限
2. 确认企信空间是否满
3. 对比能收到和不能收到的用户差异

### 模式 E：转发后数据不更新 / 渲染异常

转发报表后在企信打开报错、空白或数据是旧的。

**根因**：多级缓存未及时失效（预计算缓存 + 查询缓存 + 小程序缓存）。
**排查**：
1. 清理预计算缓存和查询缓存
2. 清理小程序/PC 客户端缓存
3. 强制刷新后确认是否恢复

### 模式 F：重复推送

同一报表一天内推送了两次。

**根因**：推送幂等校验缺失。
**排查**：查推送记录表，确认同一报表同一日期的推送次数。
**修复**：增加推送幂等校验，同一报表同一天对同一用户只推送一次。

## 排查决策树

```
订阅/推送问题
├── 完全没收到推送
│  ├── 推送记录无记录 → 定时任务调度异常（模式 A）
│  └── 推送记录存在 → 检查推送目标和渠道
│
├── 推送空白/只有表头
│  ├── web 端也无数据 → 先排查数据源问题
│  ├── web 端有数据，快照空白 → 导出权限/NPE（模式 B）
│  └── 仅手机端空白 → 客户端兼容性（模式 B）
│
├── 推送数据不准
│  ├── 日期偏移 → 时区计算偏差（模式 C）
│  ├── 数值不一致 → 快照时间窗口与报表查询时间不一致
│  └── 计算字段值不对 → 快照时计算字段未重算完成
│
├── 部分用户收不到
│  ├── 缺少报表查看权限 → 权限问题（模式 D）
│  ├── 企信空间满 → 空间问题（模式 D）
│  └── 用户 ID 解析异常 → 推送目标问题（模式 D）
│
└── 转发后数据不更新
  └── 多级缓存未失效 → 清理缓存（模式 E）
```

## 输出要求

结论中必须包含：
- Step 0 产品口径判定（当天改点次日生效 / 实时订阅不支持人员变量 / 导出身份权限）
- 推送记录状态（是否存在、推送时间、推送状态）
- web 端报表数据状态（正常/异常）
- 根因类型和证据
- 建议动作（告知次日生效/恢复调度/修复权限/清理缓存/修复时区）
- 收口必须是 `排查结论：设计如此` 或 `排查结论：需要研发处理`
