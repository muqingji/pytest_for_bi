# permission-issue：BI 数据权限问题排查

```yaml
symptom: 列表有数据但报表看不到 / 统计图无数据 / 改完权限看不到图 / 下游数据权限泄露 / 穿透查看明细为空
inputs:
 required: [tenant_id, occurred_time]
 optional: [user_id, report_id, expected_data_ids, actual_data_ids, permission_change_type]
outputs:
 signals: [product_rule_gate, permission_layer, cache_wait_ok, dt_auth_sync_status, dim_auth_code_status, permission_diff_ids, data_isolation_check]
 next_skills: [fx-ops-query, fx-ops-tracing, fx-ops-knowledge]
escalate_when:
 - 下游用户可导出其他下游数据（数据安全漏洞）→ 立即回抛 fx-ops 升级为 S1
 - 大面积权限数据缺失 → 回抛 fx-ops 评估影响面
 - 已超过对应层缓存窗口仍不生效，且产品口径已排除 → 才升级研发（收口：需要研发处理）
```

FAQ 口径互殴、未过缓存窗口、把「看不到图」和「看不到数」混成一种权限，**都不是 CH / dt_auth bug**。结论只能写 `排查结论：设计如此` 或 `排查结论：需要研发处理`。

## Step 0：产品口径门禁（先于 dt_auth / CH）

未完成本步，禁止查 `dt_auth_simple`、禁止下「权限同步失败」结论。

先问清三件事：

1. 用户是**看不到图**（列表/驾驶舱没有入口），还是**看得到图但没数 / `--`**
2. 刚改的是哪一层：加人进部门/角色/用户组、后台勾对象功能或数据权限、还是单张图/驾驶舱授权给某人
3. 改完到报障过了多久

### 0.1 三层权限，三套等待，不要合成一个时长

| 层 | 客户实际改了什么 | 生效上限 | 谁控制 | 窗口内结论 |
| --- | --- | --- | --- | --- |
| 组织成员缓存 | 人新进部门 / 角色 / 用户组 / 部门负责人；图或驾驶舱的「可见人」绑的是这个节点 | **最长 6 小时** | BI 缓存 | `设计如此`，让等 |
| PaaS 权限点 | 后台管理改对象/字段/功能/数据权限（给角色勾权限） | **最长 2 小时** | PaaS API，BI 控不了 | `设计如此`，让等 |
| 单图/单驾驶舱授权 | 把某张图或某个驾驶舱直接授权给某个人 | **10–30 分钟** | BI | `设计如此`，让等 |

不要用 6h 去否 2h，也不要用「给人加角色」去套「给角色勾权限」。预览页导出按钮「等几分钟」是经验值，上界仍按 2 小时，不构成硬冲突。

**超窗口仍不生效**才进入 Step 1 的 dt_auth / 同步排查。

### 0.2 「看不到图」≠「看不到数」

看不到图（入口没有）：

- 主题分析权限 ∩ 图表公开/私有可见人
- 报表 / 交叉表还要 ∩ 主对象功能权限

预置图表同样要主题分析权限，不是「系统预置就能看」。

看得到图但没数 / `--` / 无 toast：

- 报表数据权限走**主业务对象**
- 统计图数据权限走**主题对象**（不要拿报表那套去套统计图）
- 下游统计图经常**不弹无权限**，只是没数或 `--`，不要当成渲染失败

### 0.3 角色不要放大

- 「报表管理员」默认有对象数据权限，**不等于**全功能 CRM 管理员，也不等于图表功能权限（新建/编辑/导出/订阅）全开
- 自定义「目标管理员」≠ 预置目标管理员
- 驾驶舱开了「用管理员身份查看」会放大个人级驾驶舱数据范围，普通员工看到无权限数据时先核这个配置，不要当数据泄露

### 0.4 主题共享口径（数据权限，不是查看权限）

| 主题 | 建议口径 | 不要踩的坑 |
| --- | --- | --- |
| 人员主题 | 只走数据负责人 / 数据来源共享 | 「查看全部」对人员主题指标对象不生效 |
| 部门主题（非目标规则） | 走基于归属部门共享，多对象取交集 | 「部门主题暂不支持任何共享」是过期口径，不要用 |
| 目标主题 | 「暂不支持共享」只约束主题本身；**完成值仍走考核对象共享** | 不要用这句话直接否掉完成值可见 |
| 从对象主题 | 通常走主对象；审批流任务走任务自己 | 「共享了审批流程还看不到任务」可能是走了主对象 |

部门主题「维度显示人员不显示部门」是登录人没有该部门数据权限时的展示，不是维度丢了。

## 排查步骤

### Step 1：确认权限数据同步状态

执行入口：`fx-ops idp --profile <p> query bi-postgresql --tenant-id <EI> --sql "<SQL>" -j`（dt_auth_simple 属 PG bi biz，租户列为 tenant_id）。

```sql
-- 查 dt_auth_simple 表是否为该租户同步了权限数据
SELECT count(*) AS auth_record_count
FROM dt_auth_simple
WHERE tenant_id = '<EI>'
```

如果 count 为 0，说明权限表未同步。

### Step 2：检查 dim 表中的权限编码

> ⚠️ **schema 校准（2026-09-07 hwcloud 实测）**：CH 侧已无独立 `dim_data`（维度合入 `agg_data` 自带 `data_auth_code` 列）。下列 SQL 第一段走 PG bi（`dt_auth_simple` 属 PG bi biz；旧双表架构 CH 维表仍可用 `dim_data` 做侧证）；第二段在当前架构下改查 CH bi 的 `agg_data`。

```sql
-- PG bi：dt_auth_simple 已同步但 CH 端 data_auth_code 缺失排查
SELECT count(*) AS total_count,
    count(data_auth_code) AS has_auth_count
FROM dt_auth_simple
WHERE tenant_id = '<EI>'

-- CH bi（当前架构首选）：agg_data 自带 data_auth_code 列
-- 列名（dim_string_N/data_auth_code/life_status）以 show columns 实测为准
SELECT count() AS total_count,
    count(data_auth_code) AS has_auth_count
FROM agg_data
WHERE tenant_id = '<EI>'
  AND object_id = '<obj>'
```

如果 `has_auth_count < total_count`，说明部分维度记录缺少权限编码。

### Step 3：对比用户可见数据

1. 用管理员账号查看数据范围
2. 用问题用户账号查看数据范围
3. 对比差异数据 ID
4. 检查差异数据是否因为权限过滤被排除

### Step 4：分类根因

| 根因类型 | 特征 | 方向 |
| --- | --- | --- |
| dt_auth_simple 未同步 | 权限表为空或数据不完整 | 检查权限同步任务状态 |
| dim 缺少 data_auth_code | 维度表中部分记录无权限编码 | 检查字段是否在 stat_field 中被禁用 |
| 数据范围配置差异 | 用户数据范围与预期不符 | 检查驾驶舱/报表全局筛选配置 |
| 下游数据隔离失效 | 下游用户可看到其他下游数据 | 立即回抛 fx-ops 升级为 S1，检查导出接口权限过滤 |
| 穿透查看明细为空 | 有汇总值但点击查看明细无数据 | 检查穿透查询的权限过滤和 agg 关联逻辑 |

## 常见模式

### 模式 A：列表有数据但报表/统计图无数据

1. 确认用户的数据权限范围（部门/人员/自定义权限）
2. 检查 dt_auth_simple 表是否包含该用户的权限记录
3. 检查 dim 表中数据的 data_auth_code 是否与用户权限匹配
4. 如果权限表正常，检查报表的"数据范围"配置是否过于严格

### 模式 B：下游租户数据泄露

1. 确认下游用户可以看到哪些不属于自己租户的数据
2. 检查导出接口是否做了租户隔离过滤
3. 立即回抛 fx-ops 并建议升级为 S1，由主控决定是否通知安全团队（子技能无权自行协调外部团队）

### 模式 C：组织架构变更后权限丢失

1. 检查组织架构变更的时间点
2. 检查变更后 dt_auth_simple 表是否已重新同步
3. 检查员工的部门归属是否已更新
4. **先过 Step 0**：人刚进部门/角色/用户组，图的可见人绑的是这个节点 → 最长 6 小时组织成员缓存，窗口内不要当 dt_auth 丢了

### 模式 D：员工主题多对象统计图默认取共享最小集（交集）导致数据空白（TAPD Bug #1120019471001431295）

**表现**：员工主题首页看板/统计图明明已配置指标，但部分员工登录后看不到数据或数据缺失。

**机制与根因**：在未开启指标级权限时，员工主题统计图涉及多个关联对象时，默认权限走各底层对象可见性的**最小交集**——即用户必须同时拥有该图表关联的全部对象的数据权限；若用户对其中任一从对象无读取权限，整行聚合数据将被直接过滤。

**解决方案**：开启租户灰度项「BI统计图支持指标级数据权限」，使不同指标能够独立按单对象权限计算与渲染。

### 模式 E：改完权限看不到图 / 没有导出按钮

先按 Step 0.1 分层，不要用一个时长去套：

- 给人加进角色/部门/用户组，图对这个节点可见 → 等 6 小时
- 后台给角色勾对象功能/数据权限 → 等 2 小时（PaaS）
- 单张图/驾驶舱授权给这个人 → 等 10–30 分钟
- 标题写「看不到图表或者没有导出」但正文只覆盖导出功能权限的 FAQ，不要拿来否查看权限

窗口内：`排查结论：设计如此`。超窗口：再查主题分析权限、图表可见人、报表主对象功能权限。

### 模式 F：看得到图但统计图没数、无 toast

1. 确认走的是主题对象数据权限，不是报表主对象
2. 人员主题：只核数据负责人/来源共享，不要用「查看全部」解释
3. 部门主题非目标：核归属部门共享交集
4. 下游互联：没主题对象权限经常只是没数/`--`，不是白屏

### 模式 G：驾驶舱「管理员身份查看」放大数据

个人级驾驶舱配置了用管理员身份查看时，普通员工看到无权限数据是产品行为。先核驾驶舱配置，不要当 S1 泄露。企业级驾驶舱本身按企业范围，另论。

## 输出要求

结论中必须包含：
- Step 0 产品口径判定（哪一层权限、是否仍在缓存窗口、看不到图还是看不到数）
- 权限数据同步状态（dt_auth_simple / dim auth_code）——仅在过了 Step 0 之后
- 用户可见数据 vs 预期可见数据的差异
- 根因类型和证据
- 收口必须是 `排查结论：设计如此` 或 `排查结论：需要研发处理`
- 如果涉及数据泄露，标注严重级别并建议立即处理
