# BI 核心知识

## 数据同步链路概览

BI 数据从业务系统到仓库的关键路径：

```
业务操作 → paas-op-log → MQ 消息 → paas-bi-copier 消费 → 聚合框架 → ClickHouse 仓库 → 报表/驾驶舱
```

每个环节都可能成为瓶颈或故障点：

| 环节 | 常见问题 | 排查方向 |
| --- | --- | --- |
| paas-op-log | 日志写入延迟 / 丢失 | 源数据完整性 |
| MQ 消息 | 积压 / 消费滞后 / 消息丢失 | MQ 监控、消费 lag |
| paas-bi-copier | 同步报错 / 消费阻塞 / 重试风暴 | copier 日志、错误率 |
| 聚合框架 | 聚合任务失败 / 聚合窗口不对 / 数据覆盖 | 聚合任务状态、日志 |
| ClickHouse 写入 | 写入拒绝 / 副本不一致 / part 合并积压 | CH 集群监控 |
| ClickHouse 查询 | 慢查询 / 内存溢出 / 超时 | CH 慢查询日志 |

## ClickHouse 查询性能

报表加载慢时，排查 ClickHouse 慢查询的优先级最高。关键排查维度：

- 查询耗时分布（P95/P99）
- 扫描行数 vs 返回行数（高比值说明缺索引或过滤不够）
- 内存使用峰值
- 是否命中物化视图 / 聚合表
- 是否有锁等待或 part merge 阻塞

## 取证原则

- **先看同步链路完整性**，再查数据正确性——如果数据根本没到仓库，查 SQL 没意义
- **先看时间窗口**：同步延迟类问题，先确认"源数据写入时间"vs"仓库数据时间"的差值
- **先看 CH 慢查询日志**：报表加载慢时，先从 CH `system.query_log` 入手，再往上层追
- **对比验证**：数据不一致时，对比同一时间段内 op-log 原始记录与 CH 聚合结果
- 结论必须引用证据，证据目录沿用主控分配的 `evidence_dir`
