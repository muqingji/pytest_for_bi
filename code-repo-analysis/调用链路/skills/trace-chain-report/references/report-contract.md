# trace-chain-report 交付契约

本文件是目录、字段、事实标记和章节的唯一契约。`SKILL.md` 与批量提示只引用这里，不再单独规定路径或措辞。

## 目录

```text
<分析根目录>/调用链路/统计图/<中文描述>-<短标识>/
├── fact-card.json
├── 调用链路分析.md
├── 调用链路线性图.html
└── 证据索引.md
```

`<中文描述>` 来自调用日志里 traceId 前的文字。短标识用企业 ID、接口短名或 traceId 前 6 到 10 位，只为消歧。

## 模式

事实卡的 `mode` 只能是 `knowledge` 或 `live`。

- `knowledge`：身份、节点和资源都要能回指已有证据。没有 Pod 或监控文件，就不要补查。
- `live`：缺证据时按技能里的能力顺序补齐，并把新证据路径写进事实卡。

## 事实标记

| 标记 | 含义 |
| --- | --- |
| `已观测` | 网关、应用日志、指标或 SQL 原文直接给出 |
| `代码映射` | 源码检索命中了仓库、文件和符号；线上没有这段耗时 |
| `推断` | 由顺序或两个已观测数字的差推出，正文必须写出「推断」 |
| `未取证` | 查询为空、权限不足、span 缺失或源码不可用 |

耗时对不上时写 `未细分`。不要使用「强关联」「可能」「未证明」作为另一套标记。

## 事实卡

`fact-card.json` 的字段以 `references/fact-card.schema.json` 为准。节点至少包含 `service`、`entry`、`method`、`flow`、`downstream`、`timing`、`evidence`、`label`、`row`。

`label` 为 `代码映射` 时，节点还要有 `source.repo`、`source.file`、`source.symbol`。`row` 为 0 表示主路径，大于 0 表示并行或异步分支。

## Markdown 章节

`调用链路分析.md` 按这个顺序写。材料不够就在该节写 `未取证` 和原因，不能删节。

1. 分析对象
2. 一句话结论
3. 调用链路图
4. 请求序列
5. 节点逐条说明
6. 代码走读链路
7. 性能分解与瓶颈
8. Pod 与资源配置
9. 证据边界
10. 证据索引

第 6 节要么说明「未取得精确源码」，要么逐条对应 `代码映射` 节点。第 7 节必须出现 `未细分`。第 9 节必须出现 `未取证`。

正文不写用户标识和密码。SQL 不贴全文，但数据库名、表名、CTE 和过滤对象要留。Mongo 留数据库名和集合名。物理库名没有证据时写 `数据库名未取证`，不能省略。MQ 发送或消费必须留下 MQ 名字、发送方、消费方，缺的一侧写 `未取证`。链路证据里的 Redis、MQ、copier、ClickHouse 地址、Pod IP 和 Node IP 必须打印，不能因脱敏删掉。

## HTML

`调用链路线性图.html` 是自包含泳道图，不加载外部脚本、样式或图片。不要再用纵向分层卡片，也不要用 SVG 代替。

页面结构：

- 页头：中文标题、入口接口、状态和总耗时。右侧只放有证据的服务、Pod 和 traceId。
- 列从左到右是参与方。有证据才开列：网关、每个 PSM、每个中间件、每个远程服务。同一 PSM 的多个方法放同一列。PostgreSQL、Redis、MQ、copier、ClickHouse 各自一列，没出现就不要开。
- 同一数据库的多张表放在该中间件列。一次 SQL 连接多张表时画一张卡，每张表都写数据库名和表名，不要画成多次往返。分开的 Mapper 调用才分成多张卡。
- 数据库列和查表卡必须出现「数据库名」字段。取到物理库名就写原文；没取到写 `数据库名未取证`。数据源配置名、biz、租户可以写在旁边，但要标明不是物理库名。
- MQ 列的发送卡和消费卡都必须出现 MQ 名字、发送方、消费方。没有单独中间件证据就不要开列。
- 行从上到下是调用顺序。实线表示发出，虚线表示返回。卡片落在执行这一跳的列里。没有单独中间件的本地处理留在 PSM 列。
- 页脚写证据边界。样例页只说明列、箭头和卡片密度，不能把样例里的组件抄进当前 trace。

每张卡片只表达事实卡里的一个节点，一次连接查询可以在同一张卡里列出多张表：

- 标题是中文动作，不能只写类名。
- 正文先用中文说明这一跳的输入、结果、下游和耗时，再写上接口路径或方法名。
- 方法名、接口名、数据库名、表名、MQ 名字和地址保留原文。日志里有 Redis、MQ、copier 或 IP，就写进对应列。只在架构说明里出现、本 trace 没有 span 的，不要开列。

事实卡节点要有 `title_zh`、`detail` 和 `layer`。`detail` 必须同时含中文和方法名。`layer` 只能是 `display`、`gateway`、`service`、`data`、`offpath`。HTML 列按参与方归并，不按 `layer` 纵向堆叠。

`live` 报告至少有一张 `layer=data` 卡片，并出现在对应中间件列。有 Mapper 和 `FROM` 命中时，正文写数据库名、表名、Mapper 方法和已观测的过滤条件，不贴完整 SQL。`sql_slow_dist` 为 0 不是省略这一列的理由。源码和日志都查过仍没有表名时，仍留一张 `未取证` 卡，写明查过的方法，并写 `数据库名未取证`、`表名未取证`。出现 MQ 时，发送和消费都要写 MQ 名字、发送方、消费方。

## 精度参照

精度下限是「每个节点都能回指证据，缺失显式标出」，不是把历史样例里的推断抄过来。历史样例只说明章节和卡片应该有多具体，不能当作当前 trace 的事实。
