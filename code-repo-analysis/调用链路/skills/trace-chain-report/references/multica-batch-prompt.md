# Multica 批量 Worker 任务模板

把尖括号变量换成当前任务值后，作为 worker 的任务描述。

```text
使用 $trace-chain-report 批量分析调用链路。模式：<knowledge 或 live>。

输入：
- 调用日志记录：<路径>
- 分析根目录：<路径>
- 证据目录：<路径，没有就写无>
- 本批 trace 数：<N>

要求：
1. 每条 trace 单独建 fact-card.json，再写报告。不混用其他 trace 的 Pod、耗时、SQL 或结论。
2. knowledge 模式只读已有证据。live 模式才按 fx-ops 能力补 CEP、应用日志、调用链、SQL 和资源。
3. 输出目录固定为 <分析根目录>/调用链路/统计图/<中文描述>-<短标识>/，其中包含 fact-card.json、调用链路分析.md、调用链路线性图.html、证据索引.md。
4. 事实标记只用已观测、代码映射、推断、未取证。对不上的耗时写未细分。
5. 没有仓库、文件和符号时，不写代码映射，第 6 节标明未取得精确源码。
6. HTML 是自包含泳道图，不要画纵向分层卡片。列是网关、PSM、中间件和远程服务，行是调用顺序；实线发出，虚线返回。每张卡片用中文说明动作，并带上接口或方法名。没有证据的参与方不要开列。慢 SQL 为 0 只说明没有慢查询，必须用源码追到 Mapper 和 FROM 表。同一次 SQL 的多张表放在同一张中间件卡片里，每张表都写数据库名和表名。物理库名没有证据时写数据库名未取证，不能省略，也不能用数据源配置名或别的请求的库名冒充。源码和日志都没有表名时，中间件列仍留一张未取证卡，并写数据库名未取证、表名未取证。
7. 正文不写用户标识和密码。链路中出现的 Redis、MQ、copier 和 IP 都要打印。MQ 发送和消费必须写 MQ 名字、发送方、消费方，缺的一侧写未取证。
8. 写完后用 validate_report.py 校验。失败的 trace 标 partial，继续其余 trace。
9. 只生成本地文件。没有用户明确要求时，不上传、不创建分享链接。

完成判定：逐条返回 traceId、输出目录、complete 或 partial、关键入口、关键耗时、缺失证据，以及校验是否通过。
```

协调者按 traceId 拆任务。重跑时先读该目录的事实卡和证据索引，只补缺失项，不改写已经对上证据的句子。
