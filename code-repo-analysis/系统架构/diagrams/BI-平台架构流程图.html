图 A · BI 平台分层架构（主图，完整版）

这张图在讲什么

BI 平台 = 端上体验 + 接入网关 + 查询应用服务群 + 数据生产/计算 + 存储与中间件 + 中台依赖。 上一版问题：把少量代表服务塞进一张拥挤流程图，既不直观，也漏了大量真实服务。本版拆成：

  • A1 主链路简图：只保留主路径，先建立全局心智模型
  • A2 分层全景图：按层展示“层职责 + 主要组件族”
  • A3 完整清单表：L1–L7 尽量列全服务/中间件（含老链路与异步计算族）
重要区分： 1）业务 PostgreSQL（CRM 事务库）≠ BI PostgreSQL（图配置/元数据/规则）； 2）查询侧应用（stat/report…）≠ 大数据侧生产（copier/warehouse/DWS）； 3）新统计图主路径（xkcharts + fs-bi-stat + CH 预聚合）与老报表/老实时计算族并存。

为什么仍可能“感觉少东西”？
1）前端除 xkcharts 外还有主站仓库、驾驶舱壳、Agent 前端等，不都在 BI 六仓内；
2）同一能力可能有“新服务名 + 老服务名 + compose 合并部署”多种形态；
3）基础设施（具体 CH 集群、MQ topic 全表、K8s 拓扑）属环境配置，源码仓通常不完整。
本清单覆盖的是架构认知所需的服务与中间件全集主干部；若你点名某个环境实例名，可以再往下补部署视图。

和上一版比，补了什么

  • 补全查询侧：goal、uitype、cloud/compose、export、scheduler、transfer、devops、sqlengine 独立、privilege 模块族
  • 补全大数据侧：自定义统计 online/offline/dim 计算族、目标清洗、feed2pg、计算字段重算
