6.3 上线方案
1. 必须考虑上线方案，如果在方案设计的时候上线步骤比较复杂不好评估，可以在开发过程中逐步完善，并单独发起上线方案评审
  1. 客户端idl是否需要合入（重点关注！没合入可能block所有客户端开发）
2. 是否考虑用户维度的灰度放量步骤
3. 上线方案充分考虑回滚方案
4. 子模块，服务上线顺序，依赖关系，放量方案，小流量方案，quota限流(注意分布式限流需要有sdk接入)。
5. 如有新增AnyCache请一定观察，缓存命中率。Anycache缓存命中率平台
【上线】上线流程模板

6.3.1 止损方案
我们没有办法在上线前保障所有涉及资损问题都能够100%完全发现&解决，那么需要有一定的防御能力建设，对线上资损事故能够及时发现并拦截。如开关、回滚、紧急追回、数据修复？
6.3.2 补偿逻辑
如有补偿逻辑，设计上需注意：
- 【必须】要在订单中落补偿标记，可以用一个单独的状态，或者ext_info中有一个补偿字段。这样才能和正常的订单区分开来做数据核对。
- 【建议】要更新mod_time，表示记录的修改时间，方便快速排查问题
