# trace-chain-report 交付契约

本文件是目录、字段、事实标记和章节的唯一契约。`SKILL.md` 与批量提示只引用这里，不再单独规定路径或措辞。

## 目录

```text
<分析根目录>/调用链路/统计图/<中文描述>-<短标识>/
├── fact-card.json
├── 调用链路分析.md
├── 调用链路线性图.html
└── 证据索引.md
```

`<中文描述>` 来自调用日志里 traceId 前的文字。短标识用企业 ID、接口短名或 traceId 前 6 到 10 位，只为消歧。

## 模式

事实卡的 `mode` 只能是 `knowledge` 或 `live`。

- `knowledge`：身份、节点和资源都要能回指已有证据。没有 Pod 或监控文件，就不要补查。
- `live`：缺证据时按技能里的能力顺序补齐，并把新证据路径写进事实卡。

## 事实标记

| 标记 | 含义 |
| --- | --- |
| `已观测` | 网关、应用日志、指标或 SQL 原文直接给出 |
| `代码映射` | 源码检索命中了仓库、文件和符号；线上没有这段耗时 |
| `推断` | 由顺序或两个已观测数字的差推出，正文必须写出「推断」 |
| `未取证` | 查询为空、权限不足、span 缺失或源码不可用 |

耗时对不上时写 `未细分`。不要使用「强关联」「可能」「未证明」作为另一套标记。

## 事实卡

`fact-card.json` 的字段以 `references/fact-card.schema.json` 为准。节点至少包含 `service`、`entry`、`method`、`flow`、`downstream`、`timing`、`evidence`、`label`、`row`。

`label` 为 `代码映射` 时，节点还要有 `source.repo`、`source.file`、`source.symbol`。`row` 为 0 表示主路径，大于 0 表示并行或异步分支。

## Markdown 章节

`调用链路分析.md` 按这个顺序写。材料不够就在该节写 `未取证` 和原因，不能删节。

1. 分析对象
2. 一句话结论
3. 调用链路图
4. 请求序列
5. 节点逐条说明
6. 代码走读链路
7. 性能分解与瓶颈
8. Pod 与资源配置
9. 证据边界
10. 证据索引

第 6 节要么说明「未取得精确源码」，要么逐条对应 `代码映射` 节点。第 7 节必须出现 `未细分`。第 9 节必须出现 `未取证`。

正文不写用户标识和密码。SQL 不贴全文，但表名、CTE 和过滤对象要留。链路证据里的 Redis、MQ、copier、ClickHouse 地址、Pod IP 和 Node IP 必须打印，不能因脱敏删掉。

## HTML

`调用链路线性图.html` 是自包含分层页面，不加载外部脚本、样式或图片。不要用横向 SVG 代替这个页面。

页面从上到下固定为：

- 页头：中文标题、入口接口、状态和总耗时。右侧只放有证据的服务、Pod 和 traceId。
- 纵向层级：有卡片才渲染。顺序是展示层、网关层、服务层、数据层；请求外的链路单独放最后，并标明不在本次热路径。
- 层头用色带区分层级，层内是自动换行的卡片网格。
- 层与层之间用箭头连接。
- 页脚写证据边界，不能把样例页里的组件抄进当前 trace。

每张卡片只表达事实卡里的一个节点：

- 标题是中文动作，不能只写类名。
- 正文先用中文说明这一跳的输入、结果、下游和耗时，再写上接口路径或方法名。
- 方法名、接口名和地址保留原文。日志里有 Redis、MQ、copier 或 IP，就写进该层卡片。只在架构说明里出现、本 trace 没有 span 的，放进请求外链路，并标明不是本次调用。

事实卡节点要有 `title_zh`、`detail` 和 `layer`。`detail` 必须同时含中文和方法名。`layer` 只能是 `display`、`gateway`、`service`、`data`、`offpath`。

## 精度参照

精度下限是「每个节点都能回指证据，缺失显式标出」，不是把历史样例里的推断抄过来。历史样例只说明章节和卡片应该有多具体，不能当作当前 trace 的事实。
