# 评审报告模板

`check_review_report.py` 按本模板解析报告，章节名、字段名与符号必须逐字一致，否则脚本按缺失处理。

## 位置与命名

- 默认路径：`<需求目录>/测试方案/测试用例评审报告.md`。
- 已有同名文件时沿用，递增 `报告版本`，保留历史结论。
- 报告只写评审结论，不改被评审文档。

## 报告骨架

~~~markdown
# 测试用例评审报告

## 评审对象与版本

- 报告版本：v1
- 评审对象：测试场景清单、测试用例清单
- 对象路径：`code-repo-analysis/智能提醒助手/测试方案/测试场景清单.md`
- 对象版本：v0.1（或文件哈希）
- 评审时机：门禁 A / 门禁 B / 门禁 C / 阶段五后复审
- 前置确认：`check_test_cases.py` 已执行，阻塞项 0

## 评审范围与抽样说明

- 评审强度：standard
- 覆盖方式：P0 全量评审；P1 按覆盖维度分层抽样；P2 只核验是否已登记
- 抽样规则：每个覆盖维度至少抽一条；投诉、误发、越权类风险项强制纳入
- 漏评风险：说明本次未覆盖的条目与其可能隐藏的问题类型
- 未评审项：无 / 列出编号与原因

## 结论

- 结论：不通过
- 阻塞项：2
- 建议项：3
- 待裁定项：1
- 是否可提交人工评审：否
~~~

## 意见条目格式

每条意见一个 `###` 小节，标题必须是 `### RV-0NN 标题`，块内为无序列表字段。

~~~markdown
### RV-001 重试会产生第二次发送尝试，与“不追加第二触达”表述冲突

- 级别：阻塞
- 位置：`需求拆解/验收标准/验收标准.md:66`
- 证据：该行同时要求“发送失败最多重试一次”与“不在当天追加第二次触达”，未区分发送尝试与独立提醒
- 问题：作者按现有表述无法写出唯一预期，实现也会卡住
- 影响：AC-007 全链路用例不可判定
- 修复建议：改为“失败最多重试一次，但不得新增独立排程或第二条业务提醒，重试复用同一幂等键”
- 状态：未处理
~~~

待裁定项用同一结构，另加两个字段：

~~~markdown
### RV-006 免打扰的结果口径有两种合法写法

- 级别：待裁定
- 位置：`需求拆解/验收标准/验收标准.md:30`
- 证据：该行允许“延后到下一个可用窗口”与“返回不可提醒原因”两种结果
- 问题：场景无法写成单一预期值
- 影响：SC-023 不可判定
- 修复建议：由产品明确取其一
- 状态：未处理
- 候选方案：延后到下一窗口 / 返回 QUIET_HOURS
- 需要谁定：产品
~~~

## 字段字典

| 字段 | 必填 | 取值 |
| --- | --- | --- |
| 级别 | 是 | 阻塞 / 建议 / 待裁定 |
| 位置 | 是 | `文件:行号` 或场景、用例编号 |
| 证据 | 是 | 原文摘录或编号，不接受“经验判断” |
| 问题 | 是 | 一句话说清错在哪 |
| 影响 | 是 | 受影响的场景、用例或链路 |
| 修复建议 | 是 | 可直接指导改动；禁止“建议完善”“需要补充”这类无落点表述 |
| 状态 | 是 | 未处理 / 已处理 / 不处理（须附裁定记录） |
| 候选方案 | 待裁定必填 | 至少两个候选，用 `/` 分隔 |
| 需要谁定 | 待裁定必填 | 产品 / 技术 / 数据构造 / 用户 |

## 结论取值

| 结论 | 条件 |
| --- | --- |
| 不通过 | 存在任一阻塞项 |
| 有条件通过 | 无阻塞项，存在待裁定项或建议项 |
| 通过 | 无阻塞项、无待裁定项、无“未处理”状态的建议项 |

结论必须与意见级别一致；不一致时脚本按阻塞项处理。
