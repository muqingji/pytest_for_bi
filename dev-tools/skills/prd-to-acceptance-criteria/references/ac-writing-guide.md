# 验收标准写作指南

## 1. 文档定位

验收标准是需求冻结后的验收基线，位于这条链上：

~~~text
PRD / 产品方案 → 验收标准 → 测试方案 → 测试报告 → 质量准出
                     ↑
                技术方案（目标与测试建议引用 AC）
~~~

| 读者 | 用途 |
| --- | --- |
| QA | 据此拆分测试用例与数据构造，AC 是测试设计的上游 |
| RD | 据此判断实现是否完成、自测覆盖哪些分支 |
| PM | 据此判断需求是否可验收、能否上线 |
| 评审者 | 据此快速了解功能边界与判定口径 |

时机：PRD 冻结后、编码前定稿。范围或规则变更时，先改 AC，再改测试方案与用例。

## 2. 颗粒度规则

一条 AC 只回答一个判定问题：

| 维度 | 要求 |
| --- | --- |
| 拆分依据 | 按业务判定结果拆（发不发、发到哪、什么时间、什么原因），不按页面或按钮拆 |
| 一条一结论 | 一条 AC 只覆盖一个规则分支；多分支拆成多条，或明确写成边界各一条 |
| 前置条件 | Given 只写状态：数据、用户设置、时间、已有记录；不写操作过程 |
| 触发 | When 只写一个触发动作或时点 |
| 结果 | Then 写可观察结果：是否发送、时间落点、渠道、原因码、记录状态、事件 |
| 可判定 | 每条必须能回答"是/否"，必要时给出数字或状态词（如"最多 1 次""不在免打扰区间内"） |
| 数量 | 中等规模功能 10~20 条；每条 P0 规则至少 1 条正常分支，关键约束补 1 条边界 |

## 3. 句式模板

~~~text
### AC-0NN：一句话结论

~~~text
Given  <前置状态：任务/用户/设置/已有记录/当前时间>
And    <第二个前置状态，可为空>
When   <单一触发：生成决策 / 执行调度 / 用户点击 / 修改设置>
Then   <可观察结果：是否提醒、时间、渠道、原因码、记录状态、事件>
And    <并列结果，建议不超过 3 条>
~~~
~~~

## 4. 正反例

| 不合格写法 | 问题 | 合格写法 |
| --- | --- | --- |
| Then 提醒要及时，体验良好 | 不可判定 | Then 在用户活跃窗口内生成提醒，且早于任务截止时间 |
| When 用户打开 App 并查看任务并点击提醒 | 一个 When 塞多步操作 | When 用户点击提醒；点击后的页面跳转由测试用例覆盖 |
| Then 校验接口返回 200 且写库成功 | 写实现细节 | Then 已生成提醒记录，且原因码为 `ELIGIBLE` |
| 一条 AC 同时覆盖免打扰、频控、权限关闭 | 多结论混写 | 拆成三条 AC，各自独立判定 |
| Then 校验 Push 到达率不低于 60% | 线上统计指标不可在功能验收判定 | 归入上线后指标观察，不入 AC |

## 5. 不写什么

- 不复述 PRD 的规则原文与背景，只写"什么结果算对"。
- 不写页面操作步骤、按钮文案实现方式（文案约束可写为可判定要求）。
- 不写表名、接口名、幂等键、字段类型等实现细节。
- 不写线上统计指标（到达率、完成率提升），它们属于上线后对照实验。
- 不写测试数据的具体取值，数据构造归测试方案与数据构造说明。

## 6. 覆盖矩阵

按需求类型勾选维度，避免只写正常分支。每个维度至少有一条 AC，不适用时在该节说明原因。

| 维度 | 触发条件 | 典型结论 |
| --- | --- | --- |
| 正常分支 | 满足全部条件 | 生成提醒 / 执行业务动作 |
| 前置不满足 | 无数据、无权限、已关闭 | 不执行，并记录原因 |
| 已完成或已失效 | 已完成、已过期 | 不执行，取消未发送动作 |
| 频控与上限 | 当日已达上限 | 不重复执行，返回上限原因 |
| 重复与并发 | 重复调度、并发执行 | 幂等命中，只产生一次效果 |
| 失败与重试 | 下游失败、返回未知 | 最多重试 N 次；未知状态不盲目重发 |
| 时间边界 | 临界时间、跨天、区间端点 | 延后到下一可用窗口或按边界规则处理 |
| 设置变更 | 用户中途改设置 | 未执行的动作按最新设置重算 |
| 用户主动操作 | 延后、取消、关闭 | 生成新排程或返回不可执行原因 |
| 数据与隐私 | 展示内容 | 只出现必要信息，无敏感字段 |

## 7. 与相邻文档的边界

| 文档 | 分工 |
| --- | --- |
| PRD | 定义规则本身：什么情况下做什么 |
| 验收标准 | 定义判定：什么结果算做对了 |
| 测试方案 | 定义怎么测：分层、用例、数据、执行顺序 |
| 技术方案 | 定义怎么实现：架构、数据、接口、异常链路 |
| 测试报告 | 记录实测结果与准出结论 |
