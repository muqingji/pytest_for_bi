# 用例组成与设计方法

阶段一推导场景、阶段三展开用例时统一按本文确定"要写哪些类、每类怎么取点"。

## 1. 用例组成

场景分五类，前四类构成骨架，后两类本期允许简化：

| 场景类型 | 说明 | 本期要求 |
| --- | --- | --- |
| 正常场景 | 前置都满足、输入合法、走主路径 | 必做；必须做等价类划分 |
| 异常场景 | 前置不满足、规则拒绝、非法输入、依赖失败 | 必做；必须做等价类划分 |
| 边界场景 | 阈值临界、区间端点、跨区间、空值极值 | 必做；必须做等价类划分 |
| 性能场景 | 批量、并发、超时、容量上限 | 可简单写或跳过，但必须显式登记 |
| 回归场景 | 本次改动影响到的既有功能 | 可简单写或跳过；完整的回归范围在阶段五做 |

"简单写"指只写场景与判定点，不展开完整前置条件与预期值，并在场景里标注 `本期简化`。
"跳过"指不写场景，但必须在清单里登记一行，写明跳过原因与承接时机。

不允许的三种做法：不写、留空、默默省略。骨架三类的等价类划分不得跳过。

## 2. 等价类划分

每个可变条件都要划分，按四步做：

1. **列输入维度**：把场景里所有可变的输入条件摊开，例如用户分层、任务状态、历史行为天数、提醒开关、Push 权限、当日用量、触发来源、当前时间与截止时间的关系。
2. **分有效与无效**：每个维度划出有效等价类和无效等价类。有效类指"规则允许这样"，无效类指"规则会拒绝或走异常分支"。
3. **每类取一个代表值**：同一等价类不写多条用例。例如"任务已完成"和"任务已完成且没有历史行为"落在同一个无效类时，只取一个代表值。
4. **无效类逐条单独覆盖**：无效等价类不能合并成一条用例测，否则前一个失败会遮蔽后面的判定。

场景里用固定句式登记，便于回查：

~~~text
- 等价类：
  - 有效等价类：任务未完成、提醒已开启、Push 已授权、当日未达上限
  - 无效等价类：无任务 / 任务已完成 / 任务已过期 / 提醒已关闭 / Push 未授权 / 已达上限
  - 边界值：截止时间等于当前时间、当日用量等于上限、历史天数等于 3
~~~

示例：提醒评估的输入维度与等价类

| 输入维度 | 有效等价类 | 无效等价类 |
| --- | --- | --- |
| 任务状态 | 未完成且在截止前 | 无任务、已完成、已过期 |
| 提醒开关 | 已开启 | 已关闭 |
| Push 权限 | 已授权 | 未授权 |
| 当日用量 | 小于上限 | 等于或超过上限 |
| 历史行为天数 | 大于等于 3 天 | 小于 3 天 |
| 触发来源 | 每日评估、App 打开 | 未知枚举 |
| 用户分层 | 被动型、自驱型 | 流失型、回流首日 |

## 3. 边界值分析

等价类取代表值，边界值取临界点。每个边界至少三个点，能跨区间的再补跨区间点：

| 类型 | 取点 | 示例 |
| --- | --- | --- |
| 阈值 | 阈值本身、阈值减一、阈值加一 | 流失判定 3 天：2、3、4 |
| 区间端点 | 区间开始、区间结束、区间外一分钟 | 免打扰 21:30-07:00 |
| 跨区间 | 跨午夜、跨天、跨时区 | 免打扰跨午夜 |
| 集合 | 空集、单元素、多个元素 | 无历史行为、仅 1 天历史 |
| 时间关系 | 现在等于、早于、晚于截止时间 | 提醒时刻早于截止前 1 小时 |

## 4. 异常场景的来源

异常场景不许凭空想，来源只有四类，每条都要能指回文档：

- 文档列出的拒绝原因码与状态码；
- 技术方案的异常、降级、熔断与重试链路；
- 契约的必填、类型、枚举与长度约束；
- 依赖的失败与未知状态（超时、不可用、状态未知）。

## 5. 性能场景本期怎么写

没有压测环境和真实数据时，不要伪造性能结论。二选一：

- 简化写：只登记场景与判定点，例如"批量 50 条到期排程时单批处理不超时"，标注 `本期简化`；
- 跳过：登记一行说明"本期无压测环境，由后续性能专项承接"。

禁止把"本地跑得快"写成性能结论，也禁止用 Mock 数据推导容量水位。

## 6. 回归场景本期怎么写

首次设计时没有"历史功能"可回归，此时登记为"本期无既有功能，回归范围见阶段五影响范围评估"。
已有功能迭代时，至少要覆盖：共用同一决策逻辑、同一张表、同一份契约的既有场景。

## 7. 自检

- [ ] 骨架三类（正常、异常、边界）齐全，各自做了等价类划分。
- [ ] 无效等价类逐条单独成用例，没有被合并遮蔽。
- [ ] 边界值取够点：阈值本身、两侧、必要时跨区间。
- [ ] 异常场景都能指回文档给出的原因码、异常链路或契约约束。
- [ ] 性能与回归要么简化写、要么明确登记跳过，没有留空。
