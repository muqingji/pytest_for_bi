# 修复记录模板

写入 `docs/fixes/BUG-<编号>-<简述>.md`，并在 `docs/fixes/README.md` 的汇总表登记。
十个 `##` 小节名是回查脚本的解析依据，不要改名。

~~~markdown
# BUG-001 修复记录：<一句话描述缺陷>

## 缺陷归属

归属：业务代码 / 用例与测试资产 / 引擎或脚本 / 契约文档。
依据：<文件:行号 或 数据字段 或 文档条目>，说明为什么是这一层。

## 复现

~~~bash
<最小复现命令>
~~~

实际：<修复前观察到的结果>。
期望：<按文档或契约应该得到的结果>。
（偶现缺陷写触发条件与频率；无法复现时写「无法复现」并停止修复。）

## 根因

<根因一句话说清；写清为什么会走到这个分支，而不是只写表面现象。>

## 改动清单

- `<文件>`：<改了什么，为什么>。
- 没有改：<显式列出本次未触碰的模块、测试资产、IDL、文档>。

## 回归用例

- `<文件>_test.go:TestXxx` 或 `tests/cases/<主体>.json#<case id>`
- 修复前：红（<失败信息>）。修复后：绿。

## 验证范围

| 层级 | 命令 | 结果 |
| --- | --- | --- |
| 全量单元测试 | `make test` | 通过 N 个包，失败 0 |
| 模块集成测试 | `go test -count=1 <本轮涉及包>` | 通过 N，失败 0，跳过 0，未执行 0 |
| 竞态 | `go test -race ./...` | 通过 |
| 静态检查 | `make vet` | 通过 |
| 业务接口用例 | `make test-api-fresh` | 通过 N，跳过 M，失败 0 |
| 用例管线自检 | `make test-selftest` | 通过 N |
| 覆盖率 | `go test -covermode=atomic ./...` | 修前 x% → 修后 y% |

## CR

| finding | 级别 | 处置 |
| --- | --- | --- |
| <问题标题> | P1 | 已修（<文件:行号>） |

## 未验证

- <没跑什么、为什么>（例如真实 Push 渠道无桩、业务用例中 M 条 pending 被跳过未执行）。

## 剩余风险

<同类缺陷是否可能出现在别处；检查了哪里，结论是什么；只报告不擅自扩大修改。>

## 回滚

<代码回退方式；是否涉及迁移回退、配置开关、数据回滚。>
~~~

## 填写要求

- 「验证范围」每行都要有真实结果，不能留空或写「见上」。
- 覆盖率必须写成「修前 x% → 修后 y%」。
- 「回归用例」要给出能在仓库里定位到的凭据（测试函数名或 case id），只写「已补用例」不合格。
- CR 的 P0 / P1 处置必须是「已修」或「已关闭」；写「未修 / 后续再补 / 遗留」会被回查拦下。
- 「未验证」不允许为空；确实全部验证过时写「无未验证项」。
