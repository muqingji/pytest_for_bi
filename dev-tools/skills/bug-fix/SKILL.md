# 缺陷修复

在智能提醒助手上做一次可验证、可回滚、不越界的缺陷修复。

## Goal

一次修复必须同时成立四件事：

1. **归属清楚**：先判定缺陷属于哪一层，再决定改什么。
2. **先复现后修复**：没有可复现的证据不写修复代码。
3. **不伤其他功能**：全量单测、竞态、静态检查、模块集成测试、业务接口用例全跑，覆盖率不下降。
4. **可复核**：结论文档写清验证范围，包括没跑什么。

产出：修复代码、一条先红后绿的回归用例、修复记录（含验证范围）。

三条不变式：

- **不臆想**：复现不出、根因不明的缺陷，停下来报告，不改代码。
- **不越权**：不改与本缺陷无关的文件；不改 PRD / 验收标准 / 技术方案 / IDL；不为让测试变绿而改断言、加跳过或缩小覆盖率统计范围。
- **不静默**：改动清单、验证范围、未验证项、剩余风险、回滚方式全部写明。

## When to Use

适用：

- “修这个 bug / 修复这个缺陷”。
- “修完跑测试，然后做一次 CR”。
- “这个报错帮我定位并修掉”。

不适用：

- 实现新功能或新 FR → `tech-design-implementation`。
- 设计、评审、封板测试用例 → `test-case-design` / `test-case-review`。
- 把用例文档转成用例数据 → `test-case-to-automation`。
- 只审查不改代码 → `code-review`。

## 阶段 0：缺陷归属判定（硬门禁）

动手前先判定缺陷属于哪一层，写出能指到代码行或数据字段的判定依据。
判定问题与证据要求见 [defect-attribution.md](references/defect-attribution.md)。

| 归属 | 典型症状 | 处理 |
| --- | --- | --- |
| 业务代码 | 服务返回错的业务结果；正确输入下行为违反 PRD / AC / 技术方案 | 本 skill 主路径 |
| 用例与测试资产 | 引擎与服务都正确，是用例数据或断言写错（如漏 `path_params`、断错字段） | 转 `test-case-to-automation`，不碰业务代码 |
| 引擎或脚本 | `tests/common/`、dev-tools 脚本自身行为错 | 可修，但走本 skill 同一套验证流程 |
| 契约文档 | PRD / AC / 技术方案 / IDL 之间冲突或缺失 | 停止，退回 `prd-to-tech-design` 或发起人工确认 |

不允许跳过本阶段直接改代码：把测试资产缺陷当业务代码修，会改错地方并掩盖真实问题。

## 阶段 1：复现与影响面（门禁 A）

1. 用最小命令复现，记录命令、实际结果、期望结果。
2. 复现不出，或只能偶现 → 停止并报告，不猜着改。
3. 评估影响面：谁能触发、影响哪些 FR / AC、涉及哪些接口 / 事件 / 表 / 迁移。
4. 给出根因假设与拟改动范围（文件 + 函数），交用户确认（**门禁 A**）。

## 阶段 2：先写回归用例（红）

修复前先加一条能复现该缺陷的自动化用例，确认它是**红的**，且失败信息指向缺陷本身而不是环境：

- 领域 / 应用层缺陷 → 对应包的 `*_test.go`；
- 接口层缺陷 → `tests/cases/*.json`，写法按 `test-case-to-automation` 的规则。

这条用例是「修复完成」的唯一可信证据，修复后留在仓库里长期防复发。

## 阶段 3：最小修复

- 只改根因，不顺手重构；重构另开一次改动。
- 不改断言、不跳过用例、不缩小覆盖率统计范围来变绿。
- 根因涉及设计缺口（需要新增字段、状态、迁移或外部能力）→ 停止，退回技术方案确认。

## 阶段 4：全量验证

先启用仓库内工具链（`source scripts/go-env.sh`），或直接用 `make`。必跑项与「改了什么 → 必须跑什么」的对照见
[verification-matrix.md](references/verification-matrix.md)。

| 层级 | 命令 |
| --- | --- |
| 格式化 / 静态 | `make fmt`、`make vet` |
| 全量单元测试 | `make test`（= `go test ./...`） |
| 竞态（并发、幂等、时钟相关必跑） | `go test -race ./...` |
| 模块集成测试 | 按 `module-integration-test` 执行：`go test -count=1 <本轮涉及包>`、`go test -race -count=1 <本轮涉及包>`；迁移变更追加空库迁移、旧库升级、重复迁移 |
| 业务接口用例 | `make test-api-fresh`（自动起干净基线）；服务已在跑时用 `make test-api` |
| 用例管线自检 | `make test-selftest` |
| 契约 | 改了 IDL 时 `make lint-idl` |
| 覆盖率 | `go test -covermode=atomic -coverprofile=/tmp/fix.cover ./... && go tool cover -func=/tmp/fix.cover` |

硬性要求：

- 回归用例由红转绿；
- 覆盖率修复前后都要记录，**不得下降**；
- 业务接口用例优先用 `make test-api-fresh`：`make test-api` 复用已有进程会命中幂等返回 `REUSED`，
  同一断言两次运行结果不同；
- 集成测试与业务接口用例里的 skip / pending / 未执行都不能计入通过；
- 业务接口用例出现整体 skip（被测服务不可达）时，只能写「未获得业务结论」，不能算通过；
- 任何一项没跑，必须在「未验证」里写明并说明原因。

## 阶段 5：CR

全量测试通过后调用 `code-review` 审查**本次改动**（把基线限定在本次 diff），并逐条处置 finding：

- P0 / P1：必须修完并重跑阶段四，再交付；
- P2 / P3：可登记为已知遗留，但要写理由和后续处理方式；
- 不允许对 finding 不回应。

## 阶段 6：结论与留档（门禁 B）

修复记录写入 `docs/fixes/BUG-<编号>-<简述>.md`，并在 `docs/fixes/README.md` 汇总表登记。
记录格式见 [fix-record-template.md](references/fix-record-template.md)，必须包含归属、复现、根因、改动清单、
回归用例、验证范围、CR、未验证、剩余风险、回滚十个小节。

其中「验证范围」是给用户看的核心结论，必须包含：

- 每个验证层级的命令与真实结果；
- 覆盖率的修前与修后数值；
- 回归用例的 id 与「修复前红 → 修复后绿」；
- CR 的 finding 数与处置；
- **未验证**：没跑什么、为什么；
- **剩余风险**：同类缺陷是否可能出现在别处（检查后只报告，不擅自扩大修改）；
- **回滚方式**：代码回退 / 迁移回退 / 开关。

改动清单要显式声明「没有改什么」，把无关文件排除在本次修复之外。

交用户复核（**门禁 B**），通过后才算完成。

## 停手条件

出现以下任一情况，停止修改并报告，不猜：

- 复现不出，或复现条件不稳定（偶现）；
- 根因不明，或存在多个无法区分的候选根因；
- 根因需要改设计、加字段、加状态、加迁移或依赖新的外部能力；
- 需要改 PRD / 验收标准 / 技术方案 / IDL 才能自洽；
- 为了让测试通过必须改断言、跳过用例或缩小覆盖率统计范围；
- CR 报出的 P0 / P1 未修复；
- 缺陷归属判定为「用例与测试资产」或「契约文档」。

偶现缺陷不修代码，先补可观测性（日志、断言、复现脚本）并记录触发条件与频率。

## ToolsList

| 工具或资源 | 用途 |
| --- | --- |
| `rg`、`rg --files`、`git diff`、`git status --short` | 定位缺陷、界定本次改动范围、区分用户已有未提交修改 |
| `make fmt` / `make vet` / `make test` | 格式化、静态检查、全量单测 |
| `go test -race ./...`、`go test -covermode=atomic` | 竞态与覆盖率证据 |
| `make test-api-fresh` / `make test-api` / `make test-selftest` | 业务接口用例与用例管线自检 |
| `scripts/check_fix_record.py` | 修复记录的确定性回查，退出码当闸门 |
| `code-review` skill | 阶段五的只读审查 |
| `module-integration-test` skill | 阶段四的模块集成测试 |

## Output

| 产物 | 路径 |
| --- | --- |
| 修复代码 | 受影响模块的最小改动 |
| 回归用例 | 对应包的 `*_test.go`，或 `tests/cases/*.json` |
| 修复记录 | `docs/fixes/BUG-<编号>-<简述>.md`，并在 `docs/fixes/README.md` 登记 |
