# 产品 Leader 视角 PRD 评审清单

每次改造完成后逐项检查，并记录文件位置证据。

## 1. 来源与事实

- [ ] 产品决策是否全部来自 5 稿或用户最新确认？
- [ ] 业务背景和数据是否来自业务诉求原文或 5 稿？
- [ ] 每个数字、比例、时间和目标是否可追溯？
- [ ] 派生数据是否有公式和统计口径？
- [ ] 是否出现用户行为、调研结论或实验结果的臆造？

## 2. 范围与授权

- [ ] 是否严格在本次授权章节和改动范围内？
- [ ] 是否新增了未授权的用户、场景、前置系统、页面、渠道或权限？
- [ ] 是否改变目标用户、目标、非目标、指标或产品规则？
- [ ] P0/P1/P2 是否与 5 稿一致？
- [ ] FR/AC 编号是否被擅自新增、删除、改名或重排？

## 3. 产品表达

- [ ] 背景是否说明业务价值和当前问题？
- [ ] 用户、前置条件、行为和预期结果是否清楚？
- [ ] 用户流程和业务流程是否各司其职？
- [ ] 一个结论是否只解释一次？
- [ ] 是否存在重复、空话、堆砌概念或为了完整而过度展开？
- [ ] 文案是否符合产品经理视角，而不是技术实现视角？

## 4. 模板与追踪

- [ ] 一级章节和职责是否符合 9 稿模板？
- [ ] 每个新增或实质修改需求是否有 `5稿条目 -> 9稿章节 -> FR -> AC` 追踪？
- [ ] P0 需求是否都有验收标准？
- [ ] 待确认事项是否明确标记，没有被默默补全？

## 5. 文档边界

- [ ] 是否把 Mock、Fixture、时间注入、幂等键、表字段或调度实现写成产品需求？
- [ ] 是否把测试数据当成真实业务数据？
- [ ] 是否把技术方案、测试方案或内部分析文档中的内容反向扩展到 PRD？

## 6. 评审结论

| 等级 | PRD 位置 | 问题 | 来源证据 | 处理方式 | 是否需人工确认 |
| --- | --- | --- | --- | --- | --- |
| 阻塞/建议 |  |  |  | 修正/保留/待确认 | 是/否 |

## 准出条件

只有满足以下条件，才能报告 PRD 改造完成：

- 没有未处理的来源、范围或数据阻塞项；
- 所有新增内容都能追溯到授权来源；
- 文字无明显语病、主题清晰且无实质重复；
- FR/AC、P0/P1/P2 和模板章节检查通过；
- `git diff --check` 通过；
- 未授权改动已清理或得到用户确认；
- 待确认事项已经明确交给用户，不被伪装成确定结论。
